# 复现与学习指南

先跑一个能看懂的小案例，再追完整计算与真实CPU；直接重跑所有长任务会占用大量时间，也可能覆盖已经接受的证据目录。

## 环境与工程入口

当前工程运行于Windows上的WSL2 Ubuntu-24.04。验证环境为`.venv-dv`，官方模型环境为`.venv-model`指向的WSL原生隔离目录，两者分开使用。记录中的本地版本包括Python3.12.3、Icarus12.0、Verilator5.020、Yosys0.33；这些是本工程实际记录，不代表工具最新版本。

现有环境记录见[environment.json](../../../reports/environment/environment.json)、[环境说明](../../../reports/environment/DV_ENVIRONMENT.md)、[模型环境位置](../../../config/model-environment-location.json)。官方模型导出入口使用独立TensorFlow环境；复现RTL不需要重新安装或切换全局Python。

在PowerShell进入本工程后，可直接用下面命令进入正确WSL目录。目录名中是长横线`—`，复制完整路径可避免敲成普通连字符。

```powershell
wsl.exe -d Ubuntu-24.04 --cd "/mnt/c/Users/11035/Desktop/ic/kwt—1"
```

以下Bash命令均从工程根目录运行。先看是否已有长任务，避免与其写相同目录：

```powershell
./scripts/check_prototype_run.ps1 -Tail 1
```

此命令在PowerShell运行，只读核实际CMD/worker与日志。窗口存在不等于还在执行，以`executing`和实际命令身份为准。

## 第一步：只读查看已验证结果

不改RTL和结果，先打开：

- [硬件总报告](../../../reports/encoder/verification/report.md)：实际输入、输出范围和性能。
- [硬件状态](../../../work/encoder_status.json)：七项本地门与正式待验。

成功信号应同时包含完整输出数、零差、有限值、实际退出0和来源绑定。某层完成、部分前缀正确、同一个旧PASS文件、或`--help`成功都不能说明整项任务完成。

## 第二步：小尺寸RTL实操

在没有其他执行者写这些新目录时，运行两种模拟器的小案例：

```bash
bash scripts/run_encoder.sh --mode small --case small_3_4_8 --sim icarus --trace --output reports/encoder/reproduction/encoder-small-icarus
bash scripts/run_encoder.sh --mode small --case small_3_4_8 --sim verilator --trace --output reports/encoder/reproduction/encoder-small-verilator
```

两个目录与当前冻结验收目录不同。M3/D4/H8意味着3个token、每token4维、FFN隐藏8维，一层输出3×4=12word；attention缩放仍固定0.125，不能自行改成1/√4后再拿现有参考比较。

观察输入、权重、公开读回输出与trace。hex是IEEE binary32位模式：`3f800000`表示1.0，`40000000`表示2.0，`00000000`表示+0；不能把它们当十进制整数。测试入口会记录实际源、编译、运行、输出和比较结果，成功以该次`status.json`和实际退出码为准。

若失败，先看新目录的compile/run日志和首个差异，不先改公式或忽略flags。当前代码对计算fault、未完整装载、错误层号等有明确拒绝；清错误后仍需重新开始并完整装载，不能使用未完成输出。

## 第三步：顺着一条硬件计算链读代码

| 学习对象 | 入口 | 读到什么算理解 |
|---|---|---|
| 点积与数值表示 | [dot64](../../../rtl/dot64.sv)、[整数参考](../../../numeric/fixedpoint.py) | 能指出乘法符号扩展、累加位宽、偏置和输出转换的时机 |
| FFN1整体 | [ffn1_top](../../../rtl/ffn1_top.sv)、[报告02](02_前馈线性加速器.md) | 能解释一个输出如何遍历64个k，怎样遍历256列和99行 |
| 同步RAM | [encoder_sync_ram](../../../rtl/encoder_sync_ram.sv) | 能解释地址发出与读值使用为何相隔拍，以及为何不整体清大RAM |
| 浮点运算 | [encoder_fp32](../../../rtl/encoder_fp32.sv) | 能追请求握手、等待和响应消费，区分IEEE flags与设备fault |
| 非线性 | [encoder_nonlinear](../../../rtl/encoder_nonlinear.sv) | 能把固定exp/GELU序列对应到公式和FP32舍入步骤；LayerNorm序列在encoder_core中追踪 |
| 完整单层 | [encoder_core](../../../rtl/encoder_core.sv)、[报告05](05_单层编码器.md) | 能依次指出attention、r1/n1、FFN/GELU、r2/y的依赖 |

FP32点积固定从+0开始、k递增执行FMA，偏置最后用ADD。结合该顺序观察trace，才能判断差异来自地址、运算次序还是舍入；数学上可交换的加法在逐操作FP32下未必逐位相同。

## 第四步：完整RTL与真实E203

完整任务比小案例慢得多。先确认小案例和已有冻结证据一致，再按需要运行下列单项；新输出目录仍不覆盖正式验收目录。

```bash
bash scripts/run_encoder.sh --mode layer --attention --trace --output reports/encoder/reproduction/attention-full
bash scripts/run_encoder.sh --mode full --trace --output reports/encoder/reproduction/encoder-full12
bash scripts/run_e203_encoder.sh --policy 1 --output reports/encoder/reproduction/e203-pingpong
bash scripts/run_e203_encoder.sh --policy 2 --output reports/encoder/reproduction/e203-reload
```

独立attention应公开读回6336word；完整十二层应逐层核6336、共76032word。策略1的真实CPU只写回最终6336word，但被动神经监视器核全部76032；策略2每层真实CPU写回，共76032。两者不得交换输出数量，不能把被动trace当成CPU实际写回。

真实E203任务必须有有效固件、实际模拟器命令、逐层host请求/权重装载/START以及最终通过标记。`instructions`字段实际为IFU输出握手次数，不能算退休IPC；`bus_waits`仅是命令端背压，响应等待已计入端到端周期。

完整复现统一入口为：

```bash
bash scripts/run_formal_seven.sh --reuse-verified
```

该入口会更新其统一状态、报告并执行门禁测试；请在当前主线完全结束、没有写同目录者时使用。显式复用会核现有源和结果；若不匹配可能重新执行昂贵任务。它通过的是本地初稿门，正式平台/PPA/600/12任务仍单独待验。

官方模型重新导出或C参考重建由[export_encoder.sh](../../../scripts/export_encoder.sh)与[run_encoder_reference.sh](../../../scripts/run_encoder_reference.sh)承载。它们会写报告及部分固定测试日志，应先检查脚本和当前发布manifest；学习RTL无需重建已经冻结的模型产物。

## 失败时如何定位

| 信号 | 首先检查 | 判定后采取的动作 |
|---|---|---|
| 编译退出非零 | compile.log中第一个错误、工具版本、源列表 | 修编译原因；不能把旧binary运行结果贴到新编译 |
| 首个word不一致 | 输入/权重布局、phase、k顺序、bias时机、floathex | 缩小到首个差异所在阶段，不跳过不一致 |
| 非有限输出 | FP异常、非线性输入范围、LN方差/eps、故障状态 | 找到产生非有限值的首操作，修后重新验证受影响路径 |
| CPU卡在等待 | requested/ready层号、参数计数、START层号、WAIT_DONE/fault | 核真实握手和日志，不让TB代发CPU命令 |
| 旧PASS但验收拒绝 | 源码/实际消费物/固件/输出/日志SHA | 恢复一致版本或重跑受影响验证，不重写旧SHA |
| generic结构空壳 | CPU/两个加速窗口/共享RAM是否连接并保留 | 核层级与可达模块，不能只看Yosys退出0 |

## 学习检查与答案

1. 一层FFN1输出多少word？答案：99×256=25344；完整编码器一层为99×64=6336，两者不同。
2. 十二层是否要让全部2.39MB参数常驻512KiB？答案：不需要。每层49792word=199168B逐层装载；共享窗口复用，内部存储另按指定宏和面积预算约束。
3. SWAP为什么省搬运？答案：上一层Y已经在另一银行，翻转选择就可作为下一层X；不需要CPU读回再装载11次中间激活。
4. `flags=01`是否意味着失败？答案：它表示inexact舍入，正常FP运算常见；设备fault、ICB事务error与IEEE flags分别检查。
5. 对C逐位一致是否证明正式分类精度通过？答案：不能。它证明RTL实现本设计数值模型；还要在相同分类头下对正式600样本评估相对官方浮点参考的Top-1下降。
6. 150MHz仿真时钟是否证明时序达标？答案：不能。需要指定库和有效约束的逻辑综合时序报告、关键路径与裕量，并完成规定综合后功能检查。
