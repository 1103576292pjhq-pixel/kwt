## 验收对象与状态含义

本科生完成第1—3项；第4—7项本科自主选做、研究生必做。本工程保留本科整数FFN1主线，并实现FP32完整编码器扩展。两条路径分别说明格式、软件参考、RTL和系统验证，不能拿其中一条的精度或面积替代另一条。

| 标记 | 判定依据 |
|---|---|
| 本地功能证据齐备 | 对应实现已有实际仿真、完整输出/异常检查、来源绑定和独立回读 |
| generic结构通过 | 指定当前源能展开并保留计算、接口、CPU和推断存储结构；尚未工艺映射 |
| 本地接受待总验收 | 局部证据存在，但当前统一命令或根控接受尚未完成 |
| 正式待验 | 缺指定平台/库/评测环境等正式证据；不能升级为比赛通过 |

动态状态来自[硬件完成门](../../../work/encoder_status.json)；最终本地接受见[总体验收报告](08_总体验收报告.md)。本表陈述条款与现有证据范围，不以静态文字代替状态文件。

## 面向提交的下一步

本科优先闭合第3项正式环境：拿到组委会平台和指定库后，核接口/复位/共享窗口，完成内部SRAM宏组合、有效SDC、同版本映射网表、150MHz与面积功耗及综合后功能检查。完整编码器扩展沿用相同条件完成第7项。

现有结构、参考与复用结果可作为适配基线；正式平台适配若改变生产源或固件，相关CPU/RTL证据必须重跑，旧PASS不能改绑新版本。接入前可继续完成报告、输入和参数清单、复现入口与测量方法，不依赖虚构PPA值。

自检：共享512KB是否意味着内部RAM不能另外存在？答案：否。512KB约束共享SRAM；内部存储按指定宏实现并计入新增加速器面积预算。正式功耗还包括共享SRAM与CPU，面积预算却不计复用的固定部分，两者统计范围不同。
