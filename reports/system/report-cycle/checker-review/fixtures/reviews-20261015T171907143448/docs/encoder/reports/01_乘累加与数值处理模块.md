# 01 乘累加与数值处理模块

本模块把长度为 64 的点积变成可握手、可复位、可检查误差的硬件事务。当前整数路径已通过本地数值、边界、复位、连续任务和完整矩阵验证；这些结论覆盖冻结的工程子集，正式比赛的 600 样本及工艺指标仍待外部条件齐备后验收。

## 本章知识全景图

| 主题 | 必须先分清的概念 | 逻辑关系 |
|---|---|---|
| 实数与整数编码 | 数值、量化整数、尺度不是同一对象 | 浮点来源 → 固定尺度编码 → 整数运算 → 乘输出尺度还原 |
| 点积 | 64 个有符号乘积的和 | 先完成点积，再加一次偏置 |
| 数值处理 | 舍入减少精度；饱和限制范围 | 49 位偏置和 → sat48 → 最近偶数右移 → sat32 |
| 硬件协议 | 有效不等于已接受 | valid 与 ready 同时为 1 的上升沿才发生一次传输 |
| 验证 | 数值模型正确性、RTL 位真一致性、比赛精度是不同检查 | 独立参考 → 单元事务 → 全尺寸矩阵 → 正式统一评测 |

最短阅读路径：先手算第 3 节的 −8，再看位宽与舍入规则，最后沿状态表理解硬件怎样保证不漏第 64 项。

## 1. 赛题要求与实现边界

《2026赛题指南》印刷第 7 页正式任务 1 要求：实现长度 64 的点积、偏置及本设计需要的数值转换；数据格式、乘法器结构、累加精度和运算顺序自行确定；验证正常数据、边界、复位和连续任务，并解释舍入、溢出与误差。印刷第 7—8 页规定本科必做任务 1—3，任务 3 还包含 E203 集成和综合交付，不能把本模块通过当成本科全部必做完成。

印刷第 4—7 页同时约束：使用指定 KWT-1 冻结权重，不重训练、不微调、不蒸馏；必做计算由硬件执行；软件数值模型须与 RTL 一致；测试划分不能用于调整数值配置。来源为本机[赛题指南](../../../work/report_cycle_sources/2026赛题指南.pdf)，设计范围见[冻结设计](../../../work/formal_seven_design.md)。

本报告的主对象是 [dot64.sv](../../../rtl/dot64.sv) 与 [fixedpoint.py](../../../numeric/fixedpoint.py) 的整数路径：

| 对象 | 固定契约 |
|---|---|
| 输入与权重 | 各 64 个 signed16，二进制补码，范围 −32768…32767 |
| 偏置 | 1 个 signed48，范围 \(-2^{47}\ldots2^{47}-1\) |
| 乘积与累加 | signed16×signed16 → signed32，符号扩展后在 signed48 内累加 |
| 输出移位 | 每事务捕获一个整数 \(r\)，合法范围 0…47 |
| 结果 | signed48 原始结果、signed32 输出、两个数值范围标志及一个命令错误标志 |
| 实现结构 | 单 MAC，每次操作数握手只做一个乘积；本事务必须接受满 64 对 |

完整编码器另用 binary32 运算器，见第 7 节。两条路径共用“最近偶数”的思想，但数据格式、状态、异常含义与复位语义不同。

## 2. 从浮点来源到整数结果

### 2.1 量化整数必须带着尺度解释

输入尺度固定为 \(s_x=2^{-8}\)，即一个整数单位表示 \(1/256\)。设 \(\operatorname{RNE}\) 为最近偶数舍入，\(\operatorname{sat}_b\) 为有符号 \(b\) 位饱和，则

$$
Q_x=\operatorname{sat}_{16}\!\left(\operatorname{RNE}(X/s_x)\right).
$$

每层权重尺度 \(s_w\) 是满足 \(\max|W|\le32767s_w\) 的最小二的整数次幂；整层权重全零时使用 1。偏置尺度为 \(s_b=s_xs_w\)：

$$
Q_w=\operatorname{sat}_{16}\!\left(\operatorname{RNE}(W/s_w)\right),\qquad
Q_b=\operatorname{sat}_{48}\!\left(\operatorname{RNE}(b/(s_xs_w))\right).
$$

尺度只由冻结的 W、b 及固定规则推导，不读取样本输出、不按误差反馈搜索。权重或偏置编码若发生饱和，配置生成直接失败，不能悄悄用截断值继续。实际规则在[数值配置](../../../config/prototype-numeric.json)和 derive_layer_config 中。

为保证所有合法 signed16 输入都能使用这套层参数，计算保守界

$$
B=64\cdot32768\cdot\max|Q_w|+\max|Q_b|.
$$

要求 \(B\le2^{47}-1\)，再选最小 \(r\in[0,47]\)，使 \(\operatorname{RNE}(B/2^r)\le2^{31}-1\)。输出尺度为 \(s_y=s_xs_w2^r\)。这是固定参数范围推导，不是性能或精度调参实验。

### 2.2 位真的运算顺序

一个输出的规则为

$$
a=\sum_{k=0}^{63}Q_x[k]Q_w[k],\qquad
u=a+Q_b,\qquad
t=\operatorname{sat}_{48}(u),
$$

$$
Q_y=\operatorname{sat}_{32}\!\left(\operatorname{RNE}(t/2^r)\right),\qquad
\widehat{Y}=Q_y\,s_y.
$$

先点积、后偏置、再 sat48、RNE、sat32，顺序就是接口的一部分。输出 raw 对应 \(t\)，已经包含偏置并经过 sat48，不能把它当成尚未加偏置的累加器。

64 项乘积本身不会溢出 signed48：任一乘积绝对值不超过 \(2^{30}\)，任一部分和的绝对值不超过 \(64\cdot2^{30}=2^{36}\)，远小于 signed48 正端点。偏置可能接近 48 位端点，因此偏置相加使用 signed49；这一临时位宽是检测溢出所必需的。

RTL 将 32 位乘积显式符号扩展至 48 位；偏置与累加器各扩展一位再相加。对 \(-2^{47}\) 求绝对值时也保留 49 位，避免仍在 signed48 中求负而回绕。

### 2.3 最近偶数舍入与两级饱和

RNE 先对绝对值除以 \(2^r\)，比较余数与半值；超过半值进一，恰好半值时只把奇数商进一，再恢复符号。它关于零对称：

| 右移 1 位 | 精确商 | RNE 结果 | 判定 |
|---:|---:|---:|---|
| 3 | 1.5 | 2 | 取相邻偶数 |
| 5 | 2.5 | 2 | 取相邻偶数 |
| −3 | −1.5 | −2 | 恢复负号后仍取偶数 |
| −5 | −2.5 | −2 | 不能用向负无穷取整代替 |

shift=0 不舍入；shift=47 合法。shift=48…63 不接收操作数，直接给出 out_error=1 的错误结果，raw、data 和两个范围标志均为 0。

| 标志 | 何时为 1 | 软件应怎样解释 |
|---|---|---|
| out_overflow | \(u\) 超出 signed48，raw 被截至端点 | 累加后偏置和的范围损失 |
| out_saturated | RNE 后超出 signed32，输出被截至端点 | 输出格式范围损失 |
| out_error | 命令的 shift 非法 | 本事务无有效数值结果 |

范围损失与命令错误分开报告。例如 raw48 已饱和但大幅右移后能装入 int32，overflow 可以为 1 而 saturated 为 0。

## 3. 两个可复核算例

取 \(Q_x\) 前三项为 \(1,-2,3\)，\(Q_w\) 前三项为 \(2,4,-1\)，余下 61 项全零，\(Q_b=1,r=0\)。非零乘积为 \(2,-8,-3\)，所以

$$
a=2-8-3=-9,\qquad u=-9+1=-8,\qquad t=Q_y=-8.
$$

正确结果是 raw=−8、data=−8、overflow=0、saturated=0、error=0。必须仍送满 64 对，不能因为后 61 项为零就提前结束。真实单元波形的第一笔正是这个例子。

再取第一项 \(Q_x=Q_w=1\)，其余为零，偏置 \(Q_b=2^{47}-1\)，shift=47。此时 \(u=2^{47}\) 超出 signed48，raw 饱和为 \(2^{47}-1\)；除以 \(2^{47}\) 后 RNE 得到 1。因此 data=1、overflow=1、saturated=0。这能检查“先饱和再舍入”和两种标志的区别。

## 4. 架构、状态与时序

数据流：冻结浮点 X/W/b → 确定性整数编码与尺度 → 启动时捕获 bias/shift → 64 对输入握手 → signed48 点积 → signed49 加偏置 → sat48 → 对称 RNE → sat32 → 结果寄存器 → 消费握手 → 独立参考比较。

| 模块或逻辑 | 输入 | 输出与责任 |
|---|---|---|
| Python 数值模型 | 实数来源或合法整数数组 | 生成尺度和整数参考；标量参考使用任意精度整数 |
| product | 一对 signed16 | 一个 signed32 有符号乘积 |
| accumulator/count | 乘积及接受事件 | signed48 点积、0…63 计数 |
| FINALIZE 组合逻辑 | 更新后的完整点积、捕获的偏置与 shift | raw、data、两个范围标志 |
| OUTPUT 寄存器 | FINALIZE 结果 | 背压期间保持全部结果 |

| 状态 | 接受条件 | 行为及离开条件 |
|---|---|---|
| IDLE | start_valid 且 start_ready | 清点积与计数，捕获配置；合法任务到 COLLECT，非法 shift 到 OUTPUT |
| COLLECT | in_valid 且 in_ready | 每次接受一对操作数；第 64 次后到 FINALIZE |
| FINALIZE | 无外部握手 | 使用已经包含第 64 项的累加器，寄存结果，到 OUTPUT |
| OUTPUT | out_valid 且 out_ready | 输出被消费后回 IDLE |

启动沿不同时消费第一对操作数。第 64 对在某上升沿被接受后，下一个上升沿登记结果。这样最后一项先写进累加器，数值处理再读取它，不会少算末项。只有 OUTPUT 状态令 out_valid=1；消费者不就绪时，data、raw 和所有标志保持不变。

忙时 start_ready=0，额外 start 没有握手；非收集期 in_ready=0，额外操作数不进入计算。它们不会另产生“错误事务”。这一行为与上层 FFN1 的非法命令脉冲报错不同，使用时要按各自契约判断。

rst_n 为异步低有效复位。复位会中止未完成任务、清除输出与有效状态；恢复后须重新启动并重送完整 64 对。不能把复位前 17 对与复位后 47 对拼成一个任务。

完整端口与周期契约见 [DOT64 接口](../../../dv/dot64/README.md)。

## 5. 设计理由与误差来源

单 MAC 结构让“接受一对操作数”和“一次乘加”一一对应，面积、地址控制和验证结构容易追踪；代价是一个输出需要 64 次操作数传输，矩阵吞吐量受标量执行限制。48 位点积足以无损容纳 64 个 signed16 乘积，额外位主要用于后置偏置和的可靠溢出检测。

采用二幂尺度后，输出尺度变换可由右移完成。最近偶数在恰好半值时避免始终向同一方向取整；它仍存在量化误差，不保证每个有限样本误差相互抵消。

误差有三处来源：输入/权重/偏置编码的舍入；输出右移舍入；发生范围超限时的饱和。未饱和时，每个独立编码误差至多为本尺度的一半，输出右移的还原误差至多为 \(s_y/2\)。乘法误差还会叠加：若 \(\widehat{x}=x+e_x,\widehat{w}=w+e_w\)，则

$$
\widehat{x}\widehat{w}-xw=xe_w+we_x+e_xe_w.
$$

因此输出误差与数据大小和 64 项的累积有关，不能直接把“16 位”换算成统一百分比精度。具体精度必须对解码结果与原浮点参考计算，RTL 对整数参考的零差只证明位真运算一致。

## 7. 与完整编码器 FP32 路径的关系

完整编码器使用 [encoder_fp32.sv](../../../rtl/encoder_fp32.sv)，由 Berkeley HardFloat 实现 ADD、SUB、MUL、FMA、DIV、SQRT 及两种整数转换。它没有调用 DOT64 将整层计算量化成这里的 int16/48 规则。

| 项目 | 本报告整数 DOT64 | 完整编码器 binary32 运算器 |
|---|---|---|
| 数据意义 | 补码整数配外部尺度 | IEEE binary32 原始位 |
| 点积方式 | 64个整数乘积精确累加后加偏置 | 每步 FMA 单次舍入；点积结束后另作 ADD 偏置 |
| 范围与异常 | raw48/output32 饱和和命令 error | IEEE invalid、除零、overflow、underflow、inexact；未知op另报error |
| 有效事务 | 一次start后64对输入 | 一次req对应一个基础运算 |
| 复位 | DOT64异步低有效 | FP32 wrapper在时钟沿同步检查低有效复位 |

FP32 的范围、NaN、符号零和逐运算舍入另受[运算契约](../../../work/encoder_fp32_contract.md)约束。整数36案例的NRMSE及零差结论不能移作完整编码器的验证数量或误差结论。

## 9. 自检与答案

1. **为什么64个乘积用48位可以无损累加？** 任意部分和绝对值至多 \(2^{36}\)，小于 signed48 范围；可能超范围的是加上接近端点的48位偏置之后。
2. **shift=1且raw=−5，应输出多少？** −2，最近偶数舍入；−3是算术右移的向负无穷取整结果。
3. **bias/shift在start握手后变化，会改变本任务吗？** 不会；启动时已捕获。未握手前必须保持所提交配置稳定。
4. **第64对没有握手，能产生结果吗？** 不能；完成依据接受次数，不依据in_valid出现次数或墙钟周期。
5. **怎样区分量化误差与RTL错误？** 解码整数参考对原浮点参考衡量量化误差；RTL数据及标志对整数参考要求逐位零差。
6. **整数36例通过是否证明完整12层编码器通过？** 否；它只覆盖12组独立FFN1参数，完整编码器另含注意力、残差、LN、GELU、第二线性层和层间传递。
