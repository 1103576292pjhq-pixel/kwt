# 系统证据如何判定

- `instructions` 是真实上游核心 `ifu_o_valid && ifu_o_ready` 的取指/派发握手计数，**不是退休指令计数**。`cpu_mcycle` 是启动汇编在主程序返回后读取的硬件 CSR；`cycles` 是复位释放后直到完成邮箱响应的外部时钟周期。
- 装载提交、START、行 ACK、读写次数来自真实 E203 的系统 ICB 端口被动观察。测试台没有向该端口代发事务。
- 每项数值与 flags 先在 CPU 向共享 SRAM 的真实写事务上逐项比较；主程序结束后再次逐项检查共享 SRAM；Python 再读取全部输出文件，检查每个索引和数值。文件哈希用于复现一致性，不能替代这些比较。
- DONE 由冻结的生产驱动 `kwt1_run → wait_status(WAIT_DONE) → check_error` 检查。系统测试台独立要求主程序返回 0、BOOT 提交成功、完整数值/flags 数量正确、装载数正确、START 恰好一次、ACK 按顺序完成全部行。这里没有另外增加“被动 DONE 响应计数”字段，不把它写成已单独观测该寄存器响应的证据。
- 共享输入不含任何参考输出，输出区域以 `0xa5` 毒化。参考答案仅属于验证环境。首次运行和复跑各启动一个新的仿真进程，分别从相同固件及原始输入启动，不继承前一轮的 RAM 或控制状态。
- 当前完整 CPU 覆盖仅一个 `99×64` 乘 `64×256` 的案例及独立复跑。桥的 36 案例、原核心的 36 案例和真实 CPU 的 1 案例分别验收，不能合并称为 CPU 36 案例。
