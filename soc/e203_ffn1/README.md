# E203 与 FFN1 的真实 CPU 闭环

本验证把公共上游 E203 的系统外设 ICB 端口连接到 `rtl/ffn1_icb.sv`，系统存储 ICB 端口连接到 512 KiB 共享 SRAM 行为模型。连接在 `dv/e203_ffn1/tb_e203_ffn1.sv`，CPU 本体、ROM、ITCM、DTCM、启动汇编和驱动均复用已有冻结版本。

数据流：共享 SRAM 原始输入 → E203 执行 C 驱动 → ICB 寄存器装载 X/W/b → START → FFN1 计算一行 → CPU 读取该行全部结果及 flags → CPU 写回共享 SRAM → ACK → 最终 DONE → main 返回 → 启动汇编提交 BOOT 邮箱。

仿真器只装载固件及共享 SRAM 的原始输入。参考答案仅存在于验证环境，既不放入固件，也不放入 CPU 可见共享输入。没有测试台替 CPU 写加速器寄存器，没有直接写加速器内部 RAM，也没有以校验和替代逐项检查。

| 区域 | 地址 | 最大长度 |
|---|---|---:|
| 完成/异常邮箱 | `0xa0000000` | 20 B |
| 软件阶段标记 | `0xa0000040` | 4 B |
| M/N/shift | `0xa0000100` | 16 B |
| X，行优先 int16 | `0xa0001000` | 12,672 B |
| W，`[N][64]` int16 | `0xa0005000` | 32,768 B |
| bias，int64 容器内 signed48 | `0xa000d000` | 2,048 B |
| Y，int32 | `0xa0010000` | 101,376 B |
| flags，uint8 | `0xa0030000` | 25,344 B |
| 加速器 MMIO | `0x11000000` | 256 B 窗口 |

上述区域互不重叠，最高使用共享 SRAM 偏移 `0x362ff`，小于 `0x80000`。

运行入口：`bash scripts/run_e203_ffn1.sh`。脚本从任意工作目录定位工程，先使旧 PASS 失效，再核对依赖和上游哈希。顺序执行真实 RED、小矩阵 Icarus、同矩阵 Verilator、完整尺寸 Verilator、独立完整尺寸复跑。最终证据写到 `reports/system/e203-ffn1/`。

周期统计包含 CPU 指令、装载、总线等待、硬件计算、轮询、逐行读取和写回。仿真时钟便于执行，不是综合后的最大频率。公共 E203 的默认 PLL bypass/PMU 配置必须保持，外部桥和 SRAM 使用薄壳导出的总线时钟与复位。

边界：公共上游 SoC 尚不能证明是比赛专用平台包；共享/加速器 SRAM 使用行为模型；真实 CPU 只验证一个完整案例及复跑，不能把桥的 36 案例报告当成 CPU 36 案例，也不能据此宣称 600 样本、150 MHz 或 PPA 通过。
