# 02 前馈线性加速器

前馈第一线性层把每个 token 的64维表示投影为256维：硬件必须完成全部99行、全部256列，再把结果可靠交回调用者。本实现用一个DOT64、四个同步存储银行和逐行确认协议完成这项任务；当前36个完整层案例对整数参考逐位零差，正式统一评测与工艺指标另行验收。

## 本章知识全景图

| 核心概念 | 在本设计中的含义 |
|---|---|
| 矩阵乘法 | 每个 \(Y[m,n]\) 是X第m行与W第n列的64项点积，再加b[n] |
| 存储布局 | 数学W为[64,256]，硬件按[n][k]打包，便于连续读取一列 |
| 同步RAM | 本拍提交地址，上升沿更新读数据；控制器必须提前取数 |
| 行缓冲 | 只存当前256个输出，消费者ACK前不覆盖 |
| 十二层参数切换 | 每层重新装载对应X/W/b和shift；不等同于完整十二层编码器 |

学习主线：公式确定访问顺序 → 同步存储要求预取 → 状态机组织64次乘加 → 行缓冲限制写回时机 → 公开接口与独立参考共同验证。

## 1. 正式任务、输入输出及约束

《2026赛题指南》印刷第7页任务2规定：99×64输入乘64×256权重，加偏置后输出99×256；完成参数装载、输入缓冲、计算控制和输出写回；使用指定预训练权重与自行提取的对应层输入验证，并依次更换十二层编码器的相应参数。GELU和第二线性层属于本科选做。印刷第7—8页将任务1—3列为本科必做，任务4—7为研究生必做、本科自主选做。依据见[指南PDF](../../../work/report_cycle_sources/2026赛题指南.pdf)。

任务2的X是注意力、残差及第一处LayerNorm之后的前馈线性层输入，不是音频MFCC，也不是第一层编码器入口。[冻结设计](../../../work/formal_seven_design.md)明确保留本整数FFN1，并另建FP32完整编码器，二者不能混用输入或结果证明。

| 张量 | 数学形状 | 当前整数格式 | 元素数 |
|---|---:|---:|---:|
| X | 99×64 | signed16 | 6336 |
| W | 64×256 | signed16 | 16384 |
| b | 256 | signed48 | 256 |
| Y | 99×256 | signed32，附两个范围标志 | 25344 |

每次完整任务需要 \(99\cdot256\cdot64=1622016\) 次乘加操作数握手。默认M=99、N=256，K固定64；M=3、N=4等参数只是验证夹具，不能替代正式形状。

本实现不训练、不修改模型结构，参数转换遵循[固定数值规则](../../../config/prototype-numeric.json)。权重对应指定提交237e4097的KWT-1 best_weights，来源逐文件冻结在[模型源清单](../../../config/source-manifest.json)；原浮点基准绑定在[基准清单](../../../reports/model/baseline/manifest.json)。

## 2. 数学、数值与布局

### 2.1 每个输出都遵守同一个DOT64规则

对于 \(m=0\ldots98,n=0\ldots255\)：

$$
a_{mn}=\sum_{k=0}^{63}Q_X[m,k]Q_W[k,n],
\qquad
t_{mn}=\operatorname{sat}_{48}(a_{mn}+Q_b[n]),
$$

$$
Q_Y[m,n]=\operatorname{sat}_{32}
\left(\operatorname{RNE}(t_{mn}/2^r)\right).
$$

乘积为signed32、点积为signed48；偏置用signed49临时和检查后饱和至48位，再最近偶数舍入和32位饱和。每层使用同一个由冻结W/b范围推导的shift，解码结果为 \(Q_Ys_xs_w2^r\)，其中 \(s_x=2^{-8}\)。具体边界与例子见[乘累加报告](01_乘累加与数值处理模块.md)和[数值源码](../../../numeric/fixedpoint.py)。

overflow记录加偏置后的raw48超限，saturated记录最终int32超限。它们与每个输出一起写入行缓冲，不能只核对Y而忽略标志。

### 2.2 打包改变地址顺序，不改变矩阵定义

硬件装载和读取关系为：

$$
\operatorname{addr}_X=m\cdot64+k,\qquad
\operatorname{addr}_W=n\cdot64+k,\qquad
W_{\mathrm{pack}}[n,k]=W[k,n],\qquad
\operatorname{addr}_b=n.
$$

W在存储中按[n][k]排列，使当前输出列的64个权重连续。若误把row-major的W[64][256]原样装入，k递增时读取的就不是同一列，算出的矩阵含义会变。

例如读取 \(X[2,3]\) 的地址是131；读取数学 \(W[3,7]\) 的打包地址是451。两者的k相同，但所属银行与外层索引不同。

## 3. 架构与数据流

数据流：冻结各层FFN1输入/权重/偏置 → 整数转换与W打包 → 公开装载接口 → X/W/b同步RAM → m/n/k控制器 → DOT64 → 当前行Y/flags同步RAM → 同步逐列读回 → 匹配行号ACK → 下一行或DONE → 全部整数与标志逐项核对。

| 组件 | 输入或地址 | 功能与选择理由 |
|---|---|---|
| [ffn1_top.sv](../../../rtl/ffn1_top.sv) | 装载、start、读行、ACK | 检查任务完整性，遍历m/n/k，隔离计算与消费者速度 |
| X银行 | m×64+k | 保留全部99个token，不能只算CLS |
| W银行 | n×64+k | 一次保存本层W，99行共享同一权重 |
| b银行 | n | 为每个输出列提供后置偏置 |
| [dot64.sv](../../../rtl/dot64.sv) | bias/shift和64对X/W | 单MAC位真计算 |
| Y行银行 | n | 保存当前行32位结果及overflow/saturated |
| [prototype_sync_ram.sv](../../../rtl/prototype_sync_ram.sv) | 分时写或同步读 | 上升沿访问，便于后续明确映射同步存储 |

内部存储量按逻辑数据位计算：

| 银行 | 深度×位宽 | 位数 | 等价字节数 |
|---|---:|---:|---:|
| X | 6336×16 | 101376 | 12672 |
| W | 16384×16 | 262144 | 32768 |
| b | 256×48 | 12288 | 1536 |
| 当前Y行及两标志 | 256×34 | 8704 | 1088 |
| 合计 | 四银行 | 384512 | 48064 |

48064字节约46.94KiB，是四银行的逻辑有效位容量，未包含控制寄存器、宏的宽深补齐或物理外围。它不是“映射后SRAM面积”。SoC的512KiB共享SRAM是另一个存储空间，本表不能替代整机存储预算。

只保存一行输出避免额外配置整个99×256输出RAM；代价是计算必须等CPU读完当前行并ACK后才能继续。输入和本层权重完整保留，m递增时复用W；n递增时重新遍历当前X行。读取端口需求保持为每拍一对16位操作数，适合单MAC结构，但没有实现多输出并行阵列。

## 4. 装载、启动、执行与写回

### 4.1 完整装载是允许START的条件

公开协议见[接口说明](../../../docs/prototype/interface.md)。所有命令在上升沿采样，rst_n异步低有效。

| 信号 | 契约 |
|---|---|
| load_begin | IDLE中的单周期脉冲，建立新装载批次并清三个计数及DONE |
| load_kind | 0=X，1=W_pack，2=b；3非法 |
| load_addr | 当前银行从0连续递增的字地址 |
| load_data | signed48；X/W必须是低16位的完整48位符号扩展 |
| load_valid/load_ready | 当前可检查装载请求；是否被接受仍需通过银行/地址/数值校验 |
| loaded | loading有效，且三个银行分别写足M×64、N×64、N |
| start/shift | 完整装载后单周期启动，捕获合法shift=0…47 |
| command_error | 被拒绝命令的单周期脉冲 |

三个银行可交错写，但每个银行内部地址必须连续；重复地址、跳号、越界、非法银行和不合法符号扩展都不推进计数。load_ready=1只表示控制器处于可检查装载的阶段，不能把它当成“任意load_data都有效”。

start要求IDLE、loaded=1、shift合法，且不与load_begin或load_valid同拍。被接受后loading清零，已装载数据对当前任务锁定；下一任务必须再次load_begin并完整重载X/W/b。仅更改外部shift或遗漏某层参数不能沿用旧任务。

复位不逐字清RAM。计数、状态和有效标志清除后，旧内容无法满足START前置条件；正确性依靠有效性管理，而不是把大存储阵列做成昂贵的逐字复位。

### 4.2 同步读要求提前一拍准备操作数

| 状态 | 主要动作 | 后继 |
|---|---|---|
| IDLE | 检查装载与START | 接受START后B_REQ |
| B_REQ | 向b RAM提交n的读地址 | DOT_START |
| DOT_START | DOT64握手，捕获已读出的b[n]和任务shift | PRIME |
| PRIME | 提交k=0的X/W同步读地址 | FEED |
| FEED | MAC接受当前X/W，同时预取k+1；k=63不再预取 | 64项后RESULT |
| RESULT | 等待DOT64有效结果，写Y[n]及标志 | 下一列B_REQ或ROW_WAIT |
| ROW_WAIT | 保持完整行，允许同步读取，等待正确ACK | 下一行或IDLE/DONE |

在同一上升沿中，RAM的非阻塞赋值更新发生在MAC取样之后，因此MAC看到的是前一拍读出的值。PRIME先准备k=0，FEED才能连续消费；省掉PRIME会用旧操作数开头并错位整条点积。

对无外部停顿的内核，每输出需要B_REQ、DOT_START、PRIME、64拍FEED及等待结果的两拍RESULT，共69个控制周期。现有统计的compute为每例1748736拍，即25344×69；该局部计数不包含全部任务装载、行消费和控制开销。

### 4.3 行确认保护结果生命周期

只有本行N个结果全部写入后，row_ready才有效；row_index是当前m。计算与ROW_WAIT期间busy均为1。

在ROW_WAIT提交row_rd_en且row_rd_addr<N，紧随该上升沿的数据和row_rd_valid有效。可以连续读不同列、重复读一列或任意停顿；读数据引脚保留旧值并不表示新读成功，必须检查valid。

row_ack只有在row_ready且row_ack_index等于当前行号时有效。错误行号、计算期间ACK、消费后重复ACK都报command_error。合法ACK与读同拍时ACK优先，读被拒绝；调用者应先完成整行读取，再单独ACK。

硬件不记录“软件是否真的读过全部N列”。ACK就是消费者承担的释放承诺，生产驱动必须在Y和flags全部拷贝后再发。最后一行算完但未ACK时仍busy、done=0；最后ACK后才busy=0、done=1。DONE保持到新load_begin或复位。

## 5. 十二层参数支持及其边界

本科任务2要求依次更换十二层的对应参数，而本实现每次只运行第一线性层。现有验证将3份输入各自对应的12组X/W/b/shift，按顺序装入同一DUT连续执行；层间不重置实例，用于暴露旧计数、旧结果和旧参数残留。

这里每层X来自该层前馈第一线性层之前的浮点模型提取点。不能把第1次的99×256输出直接当第2次的99×64输入；两者不仅维度不同，中间还缺GELU、第二线性层、残差、LayerNorm和下一层注意力。

完整十二层编码器使用另一条FP32数据通路和层间缓冲，见[正式冻结设计](../../../work/formal_seven_design.md)。本报告的十二层参数测试只证明FFN1参数更新和控制复用。

### 6.2 误差和周期的解释

本地3输入×12层中，所有Y对整数参考零差；X/W/b/raw48/output32各级饱和计数均为0。最大单案例NRMSE为0.0010805182139773971，最大按层聚合NRMSE为0.0009342248801263425。定义为

$$
\mathrm{NRMSE}=
\frac{\sqrt{\frac1L\sum_{i=1}^{L}(\widehat{Y}_i-Y_i^{\mathrm{float}})^2}}
{\max\!\left(\sqrt{\frac1L\sum_{i=1}^{L}(Y_i^{\mathrm{float}})^2},10^{-8}\right)}.
$$

按层结果先合并该层三个输入的误差能量和参考能量，再计算比值，不直接平均三个NRMSE。详细误差与饱和在[向量清单](../../../reports/prototype/vectors/manifest.json)，逐案例/逐层摘要在[case-results.csv](../../../reports/prototype/case-results.csv)、[layer-results.csv](../../../reports/prototype/layer-results.csv)。

指南印刷第10页正式本科门槛为NRMSE≤3%，以全部600评测样本按12层分别汇总，再取最大；全部解码输出须有限，RTL对所交数值模型须逐位一致。印刷第11页的12个本科性能任务覆盖12层参数，每次也单独要求≤3%。当前3输入的36层案例仅用同一误差定义进行本地验证，不构成正式600样本或指定12性能任务验收。

|---|---:|---|
| load | 1654343 | 逐字装载及其间隔 |

| row_wait | 39257 | 行消费者有意等待 |

这些分类没有涵盖全部启动/ACK控制拍，不能相加后称端到端任务周期。ICB每例START之后到全部读回、ACK及有意busy负操作完成为2107743拍，不含装载；真实CPU包含装载、搬运、轮询与邮箱提交的计时在第3份报告单独给出。

## 7. 复现与结果判定

以下命令在工程根WSL环境执行，复现会更新对应证据目录；统一主线正在执行时不要同时启动：

~~~bash
.venv-dv/bin/python scripts/generate_prototype_vectors.py --verify-only
.venv-dv/bin/python dv/ffn1/run_ffn1.py --mode protocol
.venv-dv/bin/python dv/ffn1/run_ffn1.py --mode full
.venv-dv/bin/python dv/ffn1/run_ffn1.py --mode repeat
~~~

统一整数验收入口为：

~~~bash
bash scripts/run_prototype.sh
~~~

仅重新核对不变的全尺寸证据时，可由总控使用：

~~~bash
bash scripts/run_prototype.sh --reuse-verified
~~~

该模式仍执行数值、门禁、DOT64、协议及lint，并重新读取全部既有输出、计数和绑定；不会再做整批58392576次MAC仿真。生产RTL、矩阵测试台、数值代码、配置或向量变更使全尺寸旧证据失效，不能靠文档改状态恢复PASS。

成功信号必须包含本次退出码0、规定的完整案例与输出数量、真实MAC计数、全部Y及标志零差、独立复跑一致，以及运行前后源/向量指纹不变。READY_FOR_REVIEW表示等待主控复核；本整数子批独立接受见[parent-acceptance.json](../../../reports/prototype/parent-acceptance.json)，整体七项结论另由总体验收报告决定。

定位顺序是：先查[统一日志](../../../reports/prototype/run.log)与[阶段退出码](../../../reports/prototype/command-results.tsv)，再查full的run.log/process.json和具体actual.hex。进程已退出或只有历史PASS时，不能说任务仍在后台运行。

## 8. 已知边界与下一层接口

现有数据仅两份真实unknown类validation WAV和一份合成silence，覆盖36个层案例；没有正式600样本评测。小NRMSE不代表所有类别、所有音频或极端激活都同样精确。正常数据0饱和也不能取消边界测试。

单MAC与行缓冲便于证明功能，但CPU逐字装载、逐项读取及轮询开销明显；当前报告没有授权改变并行度、位宽或量化尺度。内部同步RAM尚未映射指定SRAM宏，行为周期不证明150MHz或2.25mm²预算。

交给SoC的接口是“完整装载 → start → 等行 → 逐列取Y/flags → ACK → DONE”。总线桥必须保留同步读延迟和command_error时序，生产驱动必须保证行生命周期；具体实现见[SoC集成报告](03_前馈线性加速器SoC集成与综合.md)。

## 9. 自检与答案

1. **为什么W_pack的地址是n×64+k？** 一个输出固定n、遍历k，连续保存W[k,n]能按顺序读取同一数学列；数学形状仍是64×256。
2. **装载到一半时loaded会有效吗？** 不会；三个银行的接受计数都必须精确达到规定长度。
3. **ROW_READY时busy为什么仍为1？** 当前结果尚归消费者使用，控制器必须等正确ACK，才能复用行缓冲。
4. **最后一行已经计算完，可以报告DONE吗？** 不能；必须完成最后行ACK，保证写回与消费完成。
5. **总逻辑RAM容量是多少？** \(6336×16+16384×16+256×48+256×34=384512\)位，即48064字节；不等于综合物理面积。
6. **为什么36例为912384输出、58392576次MAC？** 每例25344输出，每输出64次乘加，分别乘36得到。
7. **改了W但复用旧X能否称新一层验证？** 不能；X必须来自该层指定的FFN1输入点，W、b、shift也必须对应同一层。
