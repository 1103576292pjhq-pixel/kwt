# 本地仓库交付说明

本次将已接受的工程整理为可阅读、可核对、可继续开发的本地仓库。保留原工程的相对目录，使技术报告中的源码、向量和验收证据仍能相互定位。仓库根 README 是新位置的入口。

## 保留什么

- `rtl/`、`numeric/`、`soc/`、`sw/`、`dv/`、`tests/`、`scripts/`、`model/`、`config/`：源码、驱动、验证、数值契约、工具入口与依赖锁。
- `docs/encoder/reports/`：七项技术报告，以及需求对照、总报告、复现指南和导航，共 11 篇原始已审文档。
- `vendor/` 与 `data/`：四套冻结上游快照、原许可证、两个工程数据子集及来源记录。E203 中四个相对符号链接的目标完整保存在固定来源与交付清单中，由准备命令在 Linux 工作区恢复。
- `reports/`：报告批次清单绑定的全部文件，以及报告链接与运行输入所需的补充证据；包括部分二进制、波形和构建结果，它们承担历史结果绑定作用。
- `work/`：冻结源清单、需求与数值交接、设计/计划和历史状态，以及赛题 PDF 来源副本。

虚拟环境、工具下载缓存、编辑器配置、助手运行目录和无关的重复长回归输出未迁入。不要用通用的 `*.bin`、`*.elf`、`obj/` 或 `reports/` 忽略规则清理本交付，这些路径中包含已接受证据或必要模型数据。

## 准备与核验

| 动作 | 证明什么 | 入口 |
| --- | --- | --- |
| Linux 准备 | 从固定来源清单恢复四个链接，不下载或更改源码 | `python3 scripts/prepare_repository.py` |
| 仓库完整性检查 | 文件字节、四个符号链接、原接受清单绑定和阅读链接仍完整 | 准备后执行 `python3 scripts/verify_repository.py` |
| 历史证据回读 | 原工作区的测试、综合与独立审查结果及其边界 | [硬件接受记录](../reports/system/root-formal-acceptance.json)、[报告接受记录](../reports/system/report-cycle/root-acceptance.json) |
| 新硬件复现 | 当前目录、工具、输入和源码实际完成新的仿真/综合 | [README 快速开始](../README.md)、新输出目录中的日志与完整结果 |

交付清单位于 [config/repository-delivery.json](../config/repository-delivery.json)。清单记录所有交付常规文件的 SHA-256 和符号链接目标；清单自身不包含自己的哈希。校验器为只读操作，PASS 只说明交付完整性通过。它不是新的硬件验收或正式比赛验收。

原报告批次的 [manifest.json](../reports/system/report-cycle/manifest.json) 保持原样，其中绑定 9448 项文件。192 项生产源码的 [冻结指纹](../work/encoder_source_freeze.json) 同样保留。历史运行日志和接受记录可能包含原工作区绝对路径，供追溯使用。统一硬件门还核对历史执行路径，搬迁后不能把 `--gate-only` 当作路径无关的复验入口；也不能改写历史命令、状态或 SHA 来使它通过。

## 在本地继续工作

1. 在 WSL/Linux 中进入 `/mnt/d/github/kwt`，先运行 `python3 scripts/prepare_repository.py`，再运行完整性检查。准备命令严格比较 E203 来源清单与交付清单的链接元数据，补齐缺失链接；正确链接不变，已有普通文件不会被覆盖。`--check` 可只读检查链接是否已准备。
2. 按根 README 重建本机虚拟环境。冻结环境配置是历史记录，不代表虚拟环境已随仓库安装。
3. 先用小案例确认工具链，再逐项进行更大实验。使用 `reports/encoder/reproduction/` 下的新目录；会改写固定路径的模型、综合或总回归入口应在工作副本中运行。
4. 修改设计后，将原证据作为基线保存，为新的源码与结果建立新的身份与验收记录。此时仓库完整性检查出现已改源码哈希不同是预期信号，应先区分有意变更与意外损坏。

## Git 发布边界

仓库使用标准常规文件保存源码、报告与证据。四个 WSL 专用符号链接由根 `.gitignore` 精确排除，避免 Windows Git 在读取它们时失败；所需目标和来源指纹均随仓库提交，Linux 准备命令会重建原链接。因此，新检出不依赖原机器或外部下载，也不会把链接悄悄展开成另一个头文件副本。

根 `.gitattributes` 关闭冻结文件的自动换行转换，防止提交或检出改变 SHA 绑定的字节。新建入口说明等少数文件使用 LF。上游快照内的 `.gitignore` 为保持来源指纹而原样保留，其中部分规则会忽略权重、二进制、日志或预构建文件。首次提交按交付清单显式纳入这些常规文件，并核对暂存 blob 字节；四个生成链接不加入索引。后续新增文件也应核对清单与拟提交内容，不能仅凭普通 `git add .` 判断完整性。

这些历史证据占用较多空间，不能为了缩减体积而静默删除清单绑定成员。若以后改用独立附件归档，应同步设计归档校验与恢复步骤，再调整读者入口和发布清单。
