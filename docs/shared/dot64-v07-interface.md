# V07点积计算模块接口与验证

日期：2026-10-23。描述本次个人实现的局部计算接口，供外围对接；不声明团队已经采用此接口。

## 计算范围

一次计算小块为 `X[4,64] × W[64,16] + bias[16] → Y[4,16]`。最后不足4行时使用行mask。模块没有SRAM、权重槽、矩阵行列地址或CPU接口。

四个RTL文件均使用Verilog-2005语法：

| 文件 | 职责 |
| --- | --- |
| `rtl/compute/mul_array_4x4.v` | 16路有符号乘法、一级乘积寄存及标签同步 |
| `rtl/compute/acc_context_bank.v` | 4组上下文×4行×4列，共64个48位累加寄存器 |
| `rtl/compute/result_convert_v07.v` | 加偏置、RNE、sat16、符号扩展及一项弹性结果寄存 |
| `rtl/compute/dot64_tile_core.v` | 连接子模块，管理开始、清零、计算、排空及结果选读 |

逻辑格式沿用[numeric-format-v0.1](numeric-format-v0.1.md)：X16/Q12、W16/Q16、偏置32/Q28、累加40/Q28、输出16/Q12。48位偏置和累加、32位输出仅是物理容器。偏置必须是逻辑signed32的正确符号扩展；转换固定RNE右移16位、饱和到signed16，再符号扩展到32位。

合法K64输入的任意部分和与加偏置结果均在signed40内，因此物理48位累加无需触发逻辑饱和。转换单元还保留交接版的物理48位偏置加法溢出检测；转换单元测试中的极端48位输入是容器算术测试，不宣称为合法点积可达数据。

## 固定数据打包

- `x_i[16*r +: 16]` 是第r行当前k的X，r=0…3。
- `w_i[16*c +: 16]` 是当前上下文第c列当前k的W，c=0…3。
- `product_o[32*(r*4+c) +: 32]` 是x[r]乘w[c]。
- `ctx_i=g`对应当前16列中的第`4*g`至`4*g+3`列。
- `row_mask_i[r]=1`表示第r行有效。尾部3行示例为`4'b0111`。
- 各lane是独立signed16；打包总线整体无需声明signed，RTL在取lane后显式有符号乘法。

## 顶层端口

| 信号 | 位宽/方向 | 含义 |
| --- | --- | --- |
| clk、rst_n | 输入，各1位 | 上升沿工作，同步低有效复位，低电平须覆盖上升沿 |
| abort_i | 输入，1位 | 同步放弃当前块，清除流水及输出valid，回到IDLE |
| block_start_i、block_ready_o | 输入/输出，各1位 | 两者同时为1的上升沿接受新块；start建议一个周期脉冲 |
| block_release_i | 输入，1位 | 外围确认已读取并接收全部有效结果，请求释放当前块 |
| in_valid_i、in_ready_o | 输入/输出，各1位 | 同时为1的上升沿接收一组计算数据及标签 |
| x_i、w_i | 输入，各64位 | 4个X和4个W，低位为第0路 |
| ctx_i | 输入，2位 | 当前四列所属上下文 |
| row_mask_i | 输入，4位 | 行有效mask，同一块内保持一致 |
| block_last_i | 输入，1位 | 最后一组计算输入，正常顺序为k=63、ctx=3 |
| pipeline_empty_o | 输出，1位 | 乘积寄存级无在途有效数据；不是全模块空闲或块完成 |
| acc_ready_o | 输出，1位 | 当前块全部累加完成，允许外围选读与转换 |
| sel_ctx_i、sel_row_i、sel_col_i | 输入，各2位 | 选择一个累加值；局部列号为`4*sel_ctx_i+sel_col_i` |
| selected_sum_o | 输出，signed48 | 组合选读的偏置前累加值，仅acc_ready时按完整结果使用 |
| read_valid_i、read_ready_o | 输入/输出，各1位 | 同时为1时接收选读位置、偏置和结果标签 |
| bias_i | 输入，signed48 | 当前所选列偏置，由外围配对提供 |
| tag_i、last_i | 输入，32位/1位 | 结果身份标签和整个任务末输出标记，由外围生成 |
| out_valid_o、out_ready_i | 输出/输入，各1位 | 同时为1时下游消费一项结果 |
| out_data_o | 输出，signed32 | sat16结果的符号扩展 |
| out_tag_o | 输出，32位 | 与结果对应的tag |
| out_flags_o | 输出，3位 | bit0 overflow、bit1 saturated、bit2 last |
| out_overflow_o、out_saturated_o、out_last_o | 输出，各1位 | 与flags相同位的独立输出 |

`tag_i`作为透明标签使用，模块不解释其位含义。外围可以使用输出线性索引，但本模块不生成这个索引。若外围以8位保存flags，高5位补0。

## 一次计算的时序

1. 复位/中止释放且block_ready为1时发start。接下来的CLEAR阶段将64个累加值归零，再进入COMPUTE。
2. 外围按k=0…63发送，每个k依次发送ctx=0、1、2、3，共256次握手。对于同一个k，四次输入使用相同的4个X；外围负责X复用。
3. 每次握手产生16个寄存乘积。下一上升沿根据随乘积延迟的ctx和mask更新16个累加值。可连续每拍接收，无需等待上一组累加完成。
4. 最后一次输入携带block_last后，顶层停止接收并进入DRAIN。最后一组乘积写回后产生block_acc_done；顶层观察到完成且乘积级为空后进入READOUT。
5. acc_ready为1后，外围选择ctx/row/col并提供该列偏置、tag和last，使用read握手逐项转换。输出是一项弹性寄存器，支持每拍消费旧结果并接收新选读。
6. 外围确认有效行的结果全部消费后，撤下read_valid，再给block_release。仅在READOUT、无新read请求且无未消费输出时释放；若release被阻挡，需保持或重新发出。回到IDLE后才接受下一块。

顶层不重复维护k/g或输出计数器，不检查错误顺序、提前last、漏last、漏读或重复读。上述发送与释放约定是外围必须满足的协议，不是故障自动检测功能。无效行不应发出有效选读请求，否则模块会转换该位置的0累加值加偏置。

输入暂停时只插入空拍，已接收的乘积继续退休。结果背压时，out_valid、data、flags和tag全部保持。输入或选读遇到ready为0时，发送者应保持有效数据和标签稳定，或在尚未提供valid之前等待。

pipeline_empty可能在COMPUTE的输入空拍中为1，也可能在READOUT尚有输出等待消费时为1；用acc_ready判断计算完成，用block_ready判断是否可启动新块。

同步reset/abort具有最高优先级，在有效边沿取消当前任务和未消费输出。不能把同一边沿的旧输出当作正常退休：外围采样也必须遵循reset/abort优先的协议。异步复位源若用于系统集成，应由外围落实相应复位适配。

## 测试与复现

从本Worktree根目录运行，仅需Python3标准库、Icarus Verilog：

```bash
bash scripts/rtl/run_v07_tests.sh
```

脚本生成向量到被Git忽略的`out/v07-vectors/`，保存seed=20261023和SHA-256清单；不下载数据、不读取波形作为期望。四个.v先按`-g2005 -Wall`编译，TB按`-g2012 -Wall`编译执行。

- `tb_v07_units.sv`：400个lane乘积比较，检查符号、上下文/mask/last标签及空拍；251个转换用例和12拍连续替换，检查RNE、输出饱和、物理容器极值、flags、背压与中止。
- `tb_v07_compute.sv`：39个不同4×16计算小块，遍历全部64个累加位置；另6次恢复重算，共45次完整块、1904次有效输出握手。覆盖连续拍输入、输入暂停、上下文交替、1/2/3/4有效行、最后项、偏置、flags、输出背压、中止/同步复位恢复和受阻结果提前release保护。

顶层TB将每次选读握手的tag排入期望队列，输出消费时按队列顺序比较，检测丢失、重复和乱序；并非只按返回tag挑选参考值。可选波形命令为 `vvp out/tb_v07_compute.vvp +VCD`，生成 `out/v07_compute.vcd`。

39块的构成：原有30个点积、3个正负偏置及最后项定向用例各嵌入一个块的[0,0]，其他行列填入不同数据；再加4个全范围随机块和2个极值块。251个转换用例包含原有180个输入、7个容器/偏置边界、64个固定种子随机输入。

生成器使用Python任意精度整数及有符号floor商余数法RNE，独立于RTL取幅值法；原180个转换期望和33个点积期望均重新核对。2026-10-23还对39块的1632个有效输出逐项与队友`reference/fixed_numeric.py`标量oracle交叉检查，所有39块数值与个人`fixed_point.py`整数模型及队友向量oracle一致。

这些是局部功能验证，未包含完整99×256矩阵调度、真实SRAM宏、综合面积、150MHz STA、能耗或SoC验证。通过记录只适用于这里描述的代码和测试范围。
