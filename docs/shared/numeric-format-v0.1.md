# 点积数值格式候选 v0.1

本文件给出本轮建议基线 `i16_w16_a40_o16_rne` 的明确计算规则，供后续软件与 RTL 对齐。状态为软件候选规格；RTL 接口、时序、面积和最终提交配置仍需后续验证。

## 适用范围与维护约定

本文件作为当前个人仓库 64 点积核心开发的数值依据，规定一个输出 `y = sum(x[k] * w[k], k=0..63) + b` 的整数运算语义。它继续保持软件候选状态，不代表团队集成仓库已接受该方案，也不代表 RTL、时序或面积验收通过。

- 核心接收已经量化的 signed16 输入和权重，以及已对齐尺度的 signed32 偏置；浮点编码、模型数据提取和参数文件转换在核心外完成。
- 核心完成 64 项点积、一次偏置加法，以及本文件规定的输出舍入和饱和。
- 矩阵行列调度、SRAM 地址与访问、总线及驱动不在本数值核心范围内。并行度、流水线、握手、复位和延迟仍需单独讨论，本文件不冻结这些接口与结构。
- 配套 [JSON](numeric-format-v0.1.json) 保存程序可读取的数值配置，本文解释其含义。参考模型和 RTL 应使用同一组规则，避免各自维护不同定义。
- 本次仅补充说明，保留 v0.1 数值规则和 JSON 内容。后续若改变位宽、尺度、舍入、饱和或运算顺序，需由总控协调版本，并同步检查软件模型、RTL、转换脚本及验证向量的来源和校验值。

## Verilog 公共常量

项目共享数值头文件为 [kwt_numeric_config.vh](../../rtl/include/kwt_numeric_config.vh)。采用 `KWT_FFN_` 前缀和包含保护，集中提供 FFN 第一线性层的输入、权重、乘积、偏置、累加和输出格式；乘积位宽、乘积小数位数及输出移位量由基础常量推导。计算核心、矩阵调度和存储接口中使用相同数据对象的模块均可包含该文件，避免各模块分别定义格式。它是 v0.1 JSON 的手工对应，修改时必须核对两者一致。该格式尚未扩展到其他算子。

使用模块在文件开头写入 `` `include "kwt_numeric_config.vh" ``，编译时添加 `-I rtl/include`（从仓库根目录执行）。宏值不携带信号的有符号属性，端口、寄存器和相应运算仍须正确使用 `signed` 及符号扩展。例如在点积模块内部定义本任务长度、推导加法临时位宽并声明累加器：

```verilog
localparam DOT_LENGTH = 64; // 本任务固定为 64 项点积
localparam SUM_WIDTH = `KWT_FFN_ACC_WIDTH + 1; // 先扩展加法，再判断饱和
reg signed [`KWT_FFN_ACC_WIDTH-1:0] acc;
```

头文件只提供共享数值常量，点积长度、加法临时位宽、状态编码和流水线级数在相应模块内部管理；本任务的 64 项长度仍须遵循共享规格。RNE 和饱和逻辑仍由计算模块实现。内部累加器等寄存器通过信号连接，不需要 CPU 地址；SRAM 地址宽度、总线宽度和 CPU 可见的寄存器地址由各自接口规格规划，不在此文件定义。

## 已完成的软件验证

已比较 10 组位宽/舍入组合，并用训练数据冻结的尺度检查原模型完整验证划分的 4445 条记录。重复静音按原始 371 条记录加权，实际执行 4075 个不同输入。本候选最差层汇总 NRMSE 为 **0.0211055%**，最差单样本层任务为 **0.0319907%**；输入、输出、累加和偏置饱和计数均为零。19 项软件测试通过，12 个诊断点积另用 Python 整数逐项核对通过。

这些结果支持本候选作为 RTL 起始规格；尚不代表 RTL、面积、150 MHz 时序或组委会未公布评测样本通过。

## 位宽与尺度

所有数为有符号二进制补码，零点为 0。解码值等于“编码整数 × 对应尺度”。本轮训练标定得到的 12 层尺度相同：

| 对象 | 位宽 | 尺度 | 说明 |
| --- | ---: | --- | --- |
| 输入 X | 16 | `2^-12` | 可表示约 `[-8,8)` |
| 权重 W | 16 | `2^-16` | 可表示约 `[-0.5,0.5)` |
| 精确乘积 | 32 | `2^-28` | 乘法后不截断、不舍入 |
| 偏置 b | 32 | `2^-28` | 已与乘积尺度对齐 |
| 累加器 | 40 | `2^-28` | 包括加偏置阶段 |
| 输出 Y | 16 | `2^-12` | 从累加结果右移 16 位转换 |

以上用“位宽＋尺度”表示，避免不同 Q 格式记法对符号位的歧义。配置来源是训练集峰值加 12.5% 余量，按二进制尺度取值；验证集不拟合尺度。每层仍有独立的权重和偏置。

## 一个输出的运算顺序

```text
A = 0
按 k=0..63：
    P = 精确有符号乘法 X_int[k] * W_int[k]   # signed32
    A = sat40(A + sign_extend(P))
A = sat40(A + sign_extend(b_int))
Y_int = sat16(RNE_shift_right(A, 16))
```

`satB(v)` 将值限制到 `[-2^(B-1), 2^(B-1)-1]`。偏置加法和累加加法须先在足够宽的临时数中形成结果，再判断饱和。

`RNE_shift_right(v,s)` 的定义：先取非负幅值 `m=abs(v)`，求 `q=m>>s` 和余数 `r=m mod 2^s`。若 `r>2^(s-1)`，或 `r==2^(s-1)` 且 `q` 为奇数，则 `q` 加 1；最后恢复符号。`s=0` 时原值返回。不能简单用负数算术右移替代此规则。

例如右移 1 位：`+1→0`、`+3→2`、`+5→2`、`-1→0`、`-3→-2`、`-5→-2`。取幅值时也需承载最小负数的正幅值。

## 为什么输出采用 RNE 右移 16 位

尺度描述一个编码整数单位代表的实际数值。输入与权重相乘时，尺度相乘：`2^-12 * 2^-16 = 2^-28`。累加和偏置均保持 `2^-28`，因此设加偏置后的累加整数为 `A_int`，其实际值为 `A_int * 2^-28`。

输出的实际值为 `Y_int * 2^-12`。为使转换前后尽量表示同一数值，需要：

```text
A_int * 2^-28 ≈ Y_int * 2^-12
Y_int ≈ A_int * 2^-16 = A_int / 65536
Y_int = sat16(RNE_shift_right(A_int, 16))
```

移位量来自小数位数差 `28 - 12 = 16`；输出位宽则决定最终整数范围 `[-32768, 32767]`。例如实际结果为 `1.0` 时，累加编码为 `268435456`，转换后输出编码为 `4096`；二者分别乘以各自尺度，均表示 `1.0`。

RNE（round to nearest, ties to even）选择最近整数；恰好位于两个整数中间时，选择偶数。当前右移 16 位的例子如下：

| 加偏置后的 A_int | A_int / 65536 | RNE 后的整数 | sat16 后的 Y_int |
| ---: | ---: | ---: | ---: |
| 32768 | 0.5 | 0 | 0 |
| 98304 | 1.5 | 2 | 2 |
| 163840 | 2.5 | 2 | 2 |
| -98304 | -1.5 | -2 | -2 |
| 2147483648 | 32768 | 32768 | 32767 |
| -2147549184 | -32769 | -32769 | -32768 |

上表的 `A_int` 是 signed40 累加结果，不是 signed32 偏置。乘积不提前舍入；完成全部累加和偏置加法后，再进行一次输出 RNE，最后执行输出饱和。直接截取低 16 位、仅做算术右移，或在每次乘加后转换到输出尺度，都不等价于本规则。

## 浮点到编码的离线转换

输入、权重和偏置均按 `satB(round_ties_to_even(real × 2^fraction_bits))` 编码。参数转换和误差统计在计算机端进行，RTL 的规定点积、偏置和输出转换由硬件完成。

参考实现为 [fixed_point.py](../../scripts/model/fixed_point.py)。整数矩阵计算的加速路径只在证明所有合法编码输入和给定权重的每个部分和均不溢出后启用；否则逐项执行饱和。它不改变数值模型的运算定义。

## 存储和验证

- 矩阵元素顺序：`X[i,k]` 偏移 `i*64+k`，`W[k,j]` 偏移 `k*256+j`，`Y[i,j]` 偏移 `i*256+j`，偏置按 `b[j]`。
- 基线参数目录中 `W.npy` 为小端 int16，`b.npy` 为小端 int32；诊断向量 `dot64.npz` 保存 64 个编码输入、64 个编码权重、偏置和期望整数输出。
- NPY/NPZ 含文件头，不是直接送入 SRAM 或 `$readmemh` 的格式；总线打包、SRAM 端口和握手接口尚未在本文件确定。
- RTL 要与整数软件模型逐位一致；与浮点参考之间则按 NRMSE 评估误差，两者是不同的检查。
- 已入库的多层尺度见 [冻结配置](../reports/20261018-fixed-point-v1/candidate_scales.json)，比较与完整验证结论见 [报告](../reports/20261018-fixed-point-v1/README.md)。少量可独立使用的 [点积向量](../../tests/fixtures/dot64-v0.1/README.md) 不依赖完整数据集；完整 W/b 和矩阵缓存仍保留在工作区 `generated/quantization/20261018_fixed_point_v1/`。

本候选优先保留数值精度，并使用自然的 16 位参数存储。它不是已证明的面积或吞吐量最优方案；后续可在同一规则框架中对照较低位宽方案。
