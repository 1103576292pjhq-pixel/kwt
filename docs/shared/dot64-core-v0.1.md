# 64点积核心功能与接口说明 v0.1（历史版本）

> 2026-10-23：对应旧RTL及TB已从当前工作树删除。本文保留原版设计及测试证据，文件清单、接口和命令仅适用于Git提交480bda3中的历史版本，不适用于正在开发的V07实现。

更新日期：2026-10-22。本文描述个人仓库当前RTL的实际行为，供学习、测试和后续集成参考；不冻结团队接口，不修改共享数值规则。

## 1. 功能范围与当前状态

核心计算一个输出：

```text
y = Σ(x[k] × w[k]) + b，k = 0…63
```

硬件完成64项精确有符号乘法与累加、一次偏置加法，以及RNE舍入和16位输出饱和。输入已经量化为整数。完整矩阵的行列调度、SRAM访问、CPU寄存器、总线和驱动由其他模块负责。

当前属于“核心运算实现并通过现有功能测试”的开发版本；尚未完成综合面积、150MHz时序和平台集成验收，不能据此宣布赛题第一项全部验收完成。个人数值候选与团队方案的差异仍需总控协调。

## 2. 文件与结构

| 文件 | 用途 |
| --- | --- |
| `rtl/include/kwt_numeric_config.vh` | 公共位宽和尺度常量 |
| `rtl/compute/mul_unit.v` | 带结果寄存器的16×16位有符号乘法器 |
| `rtl/compute/dot64_core.v` | 数据接收、64项计数、累加、偏置和完成控制 |
| `rtl/compute/result_convert.v` | 40位累加结果到16位输出的组合转换逻辑 |
| `tb/dot64/` | 乘法器、转换单元、完整核心测试平台 |

核心复用一个乘法器。每接收一对输入，先寄存乘积，再在下一拍累加，依次处理k=0…63。最后一次更新执行：

```verilog
accumulator <= accumulator + mul_result + dot64_bias_i;
```

此处旧accumulator含前63项，mul_result为第64项，因此偏置在完整点积之后加入，且只加一次。转换模块直接连接accumulator，采用组合输出，没有独立CONVERT状态或最终输出寄存器。输出在运算途中可能变化，使用方依据done_o采样。

## 3. 数值规则

依据[数值规格v0.1](numeric-format-v0.1.md)及其[JSON](numeric-format-v0.1.json)。所有数据使用有符号补码。

| 对象 | 位宽 | 尺度 |
| --- | ---: | --- |
| X | 16 | 2^-12 |
| W | 16 | 2^-16 |
| 精确乘积 | 32 | 2^-28 |
| 偏置 | 32 | 2^-28 |
| 累加器 | 40 | 2^-28 |
| 输出 | 16 | 2^-12 |

数值语义是按k递增执行乘加、每次执行sat40，然后加偏置并执行sat40，最后RNE右移16位并sat16。当前合法输入的任意部分和及加偏置结果均不会溢出40位：绝对值保守上界为64×2^30+2^31，小于2^39。因此当前固定格式不需要实际触发累加饱和，最后一项与偏置合并在同一次更新中与上述数值语义等价。RTL没有通用的40位溢出饱和检测；若以后增加点积长度或改变输入位宽，必须重新评估，不能直接沿用此结论。

RNE表示最近取整，恰好居中时取偶数。转换单元先取幅值，除以65536取得商q和余数r；r大于32768，或等于32768且q为奇数时，商加1。随后恢复符号，限制到[-32768,32767]。例如98304转换为2，163840转换为2，-98304转换为-2。

## 4. 顶层端口

| 信号 | 方向/位宽 | 使用约定 |
| --- | --- | --- |
| clk | 输入，1位 | 上升沿工作 |
| rstn | 输入，1位 | 低有效异步复位 |
| clear_i | 输入，1位 | 同步清除当前任务，优先于start和累加 |
| start_i | 输入，1位 | 仅IDLE状态接受；建议发一个时钟周期脉冲 |
| busy_o | 输出，1位 | DATA_WAIT、MUL_WAIT、DONE期间为1；clear期间被组合屏蔽为0 |
| done_o | 输出，1位 | DONE期间为1，正常情况下持续一个周期 |
| data_valid_i | 输入，1位 | 当前一对X/W有效 |
| data_ready_o | 输出，1位 | DATA_WAIT期间为1；clear期间为0 |
| dot64_input_i | 输入，signed16 | 当前x[k]整数编码 |
| dot64_weight_i | 输入，signed16 | 当前w[k]整数编码 |
| dot64_bias_i | 输入，signed32 | 当前任务偏置，需由上游保持稳定 |
| dot64_result_o | 输出，signed16 | 转换结果，done有效时采样 |

当前权重端口声明引用X宽度宏；当前X/W均为16位，接口与测试一致。未来若两者位宽不同，需要同步检查端口声明及整个数值实现，当前版本不是任意位宽可配置核。

## 5. 一次任务的使用顺序

1. 复位释放且clear_i为0后，等待核心空闲。在IDLE的上升沿采样start_i=1启动任务，同时累加器和计数器归零。启动边沿不接收第一个数据对。
2. 按k=0…63提供输入和权重。在上升沿前data_valid_i和data_ready_o同时为1时接收一对数据；未接收时上游保持有效数据稳定。可以暂停提供数据。
3. 偏置未在启动时锁存，实际在最后一次累加边沿使用。本版本约定上游从start前一直保持正确偏置至done，测试也遵循此约定。
4. 最后一次累加边沿更新accumulator并进入DONE，随后组合转换结果稳定。下游在done_o为1的上升沿接收dot64_result_o，必须满足正常的建立/保持时间要求。
5. DONE期间busy_o仍为1，不接受新start；随后回到IDLE。下一任务可直接启动，无需再次复位。

没有输出ready或背压端口，下游必须及时接收完成结果。start在忙时不会排队；如果一直保持为1，回到IDLE后会再次启动，因此上游应使用脉冲。

## 6. 状态与周期关系

| 状态 | 行为 | 后续状态 |
| --- | --- | --- |
| IDLE | 等待启动 | start有效后到DATA_WAIT |
| DATA_WAIT | ready=1，接收一对X/W并寄存乘积 | 成功接收后到MUL_WAIT |
| MUL_WAIT | 等待mul_valid并累加 | 前63项返回DATA_WAIT；第64项加偏置后到DONE |
| DONE | done=1、busy=1，供下游接收结果 | 下一拍返回IDLE |

无输入暂停时，每两拍接收一对数据。设接收start的上升沿为E0，则第一个数据对在E1接收、E2累加；最后一个数据对在E127接收、E128累加并进入DONE。下游可在E129上升沿看到done=1并采样结果，该边沿之后核心回到IDLE；最早E130接受下一次start。这是当前RTL结构的周期推导，并非固定延迟接口承诺；输入暂停会延长任务时间。

组合转换路径需要在DONE周期内满足下游采样时序，功能仿真不能证明其满足150MHz。

## 7. 清除与复位

rstn拉低会异步清除状态、计数器、累加器及乘法器寄存器。clear_i被时钟上升沿采样时清除核心状态、计数器和累加器，同时其高电平期间组合屏蔽busy、ready、done和乘法使能。clear有效期间即使busy为0也不能发起有效任务。

clear_i不会直接复位乘法器内部寄存器；当前控制流程在返回IDLE和重新启动后不会累加被中止任务遗留的乘积，这一恢复场景已测试。被中止任务不保证输出完成脉冲；上游应丢弃该任务并重新提供完整64对数据。clear脉冲必须覆盖至少一个上升沿，不能把短于时钟采样窗口的脉冲当成可靠同步清除。

复位释放的同步处理属于后续平台集成需要落实的时序要求。

## 9. 复现方法

在VS Code的WSL终端运行：

```bash
cd '/mnt/d/嵌赛芯片设计赛道/kwt1-accelerator-2026/worktrees/dot64-core'
mkdir -p out
iverilog -g2012 -Wall -I rtl/include -s tb_dot64_integration -o out/tb_dot64_integration.vvp rtl/compute/mul_unit.v rtl/compute/result_convert.v rtl/compute/dot64_core.v tb/dot64/tb_dot64_integration.sv && vvp out/tb_dot64_integration.vvp
```

全部通过时最终输出：

```text
PASS: all dot64 integration checks completed
```

```bash
vvp out/tb_dot64_integration.vvp +VCD
gtkwave out/dot64_integration.vcd
```
