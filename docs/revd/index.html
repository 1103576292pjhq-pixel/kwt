B. 约束、性能和应当采纳的风险

外部意见 合并结论
大容量内部存储最终必须映射指定16位宏 采纳。本轮先做16位bank/同步读/端口预算，后续替换真实宏。行为数组存在不等于正式合规，也不应因此停止原型开发。[S01]
应消除不必要的双引擎面积 采纳为构建配置要求。保留源文件用于基准；未来本科top不同时实例化完整FP32编码器和旧整数引擎。独立固定配置的新增逻辑/内部宏都计面积；不是用到哪个只算哪个。[S01][S10]
应统一矩阵算子 采纳为长期架构目标。先统一原语/未截断部分和接口，当前只做K64；未来分阶段支持K99、K256、转置和算子特有后处理。[S07]
必须先淘汰FP32才能继续 不采纳为当前前置条件。赛题明确允许定点、浮点、混合精度。完整FP32基线有验证价值；后续新数值模型、组件RTL、全模型精度、PPA均通过后才选最终方案。[S01][S11]
FP32权重字节是INT16两倍 同形状且紧凑打包时成立。实际包中还含bias、scale、LN系数、填充；若CPU仍每个16位元素执行32位事务，总线事务未必减半，更不能保证总任务快两倍。
算法复用和双缓冲可以提高效率 采纳但要测量。已有交换实验只降低本地端到端周期2.16%左右；当前单MAC和逐字事务还需要核心/接口分开优化。逻辑读取次数不是能耗。[S11]
两块16×4096就足够 只对一张99×64 INT16张量的容量成立。不是完整编码器工作集，也不是自动满足每拍四行供数。不过CTX4确实允许更少X读存储体，RevD新增XP2利用该机会；见MEMORY_PORTS。
十二层之间都无需写回激活 仅完整编码器和正确生存期管理下的策略。独立FFN1任务Y是99×256，下一任务X是另一层提取的99×64；绝不能直接相连省略中间算子。正式12任务须冷启动。[S01][S11]

C. 最重要的评分修正

NRMSE≤3%是门槛，不是满分线。本科精度子项10分，零误差得10分，每增加0.3个百分点扣1分；到3%时精度子项为0分，但仍可能刚好满足数值准入。正式样本和其余功能/时序/面积条件仍需通过。[S01]

Top-1下降≤2是“2个百分点”，不是相对下降2%。零下降得10分，每下降0.2个百分点扣1分；下降2个百分点时该精度子项也为0分。软件工具用正确样本数检查边界，避免把百分比、比例和百分点混用。[S01]

本科只必须完成任务1—3，不要求为了创新满分先扩完整注意力。不能让“算子统一”的良好方向挤占本轮独立核优化及最后必做验收。[S01]

KWT RevD｜合并后的优化总计划

默认主线沿用既定本科FFN1任务，不将本轮扩大成完整定点Transformer。

本计划吸收外部评估中的SRAM、算子复用、量化和实验建议，同时修正其事实错误。基础是已交付的RevC；旧FP32、CPU、总线与验证记录均保留。当前目标仍是独立核V1/V2，后续再接E203和做工艺综合。

1. 最终决策

当前候选：16位整数、4×4广播式输出驻留阵列、四上下文轮换CTX4、16列权重分块、双W/双Y缓冲。保留基础micro和2×4作为对照，不在软件读取次数上就宣布PPA最优。

新增可选XP2：在CTX4稳定后，尝试把X从四个独立存储体改成两个16位存储体，用两拍读取四行并保持一个向量，计算四组输出通道期间预取下一k的向量。不增加MAC，也不改结果。它借用了用户评估里“两块4096容量足够”的事实，但补齐了端口、预取时限和生命周期。[D]

这里[D]表示本轮推导/候选；[Sxx]/[Wxx]来源见docs/SOURCES.md。架构和数据统计不是RTL实测。

3. 当前必须保持的数值契约

sum64(X16*W16) → signed49加bias48 → sat48 → RNE右移0..47 → sat32 + flags。[S05]

输出数据、overflow、saturated全部对照；不能只比Y或校验和。输入合法范围为-32768..32767。数学点积最坏正值64×2^30=2^36，至少需要38位signed精确表示，48位有余量；偏置与点积相加仍需49位临时值。

对于每个输出，micro和CTX4都按k递增，偏置只加一次、饱和只在约定位置。量化位宽、scale、shift、偏置契约不随架构开关变化。本轮INT8不启用。

V0 Python整数模型是后续RTL黄金参考；包内软件模型仅作辅助。旧FP32 C参考是独立的数值方案，与官方TensorFlow误差单列，不能要求新INT16方案逐位等于FP32。[S04][S05][S07]

4. 当前计算组织及量化候选的隔离

4×4每拍读四个X和四个W，执行16乘加。基础micro先遍历输出列组再遍历k；CTX4交换两层循环，每个k保持X并服务四组输出列，各组都有自己的48位部分和。

M99/K64/N256、PM4/PN4 micro CTX4
理想发射槽位 102400 102400
数学有效MAC 1622016 1622016
X标量读取 405504 101376
W标量读取 409600 409600
X/W合计 815104 510976
活跃部分和 96 B 384 B
一份快照 96 B 384 B

最后一组四行只有三行有效，禁止读取未初始化的虚拟行。X读取减少75%不等于总能耗减少75%；CTX4增加上下文选择和寄存器活动。XP2不再减少这101376次X标量读取，它改变存储体组织、宏组合与读取时间安排。

最小阵列先不重叠后处理；正确后共享流水后处理和快照。随数据携带task、row_group、k、g、valid、first/last与row mask；最后乘积退休后才允许完成快照。多拍反馈可能产生RAW冒险，必须按实际反馈延迟检查，不凭四上下文自动认为足够。

5. V1与V2存储

V1先用全X/full W，隔离验证计算与CTX4。V2把W改成16列一块；外层遍历权重块，内层遍历全部99行，从而每个W/b每任务只装一次。

LOAD_X_ALL
LOAD_TILE0; TILE_COMMIT; START
for nt in 0,16,...,240:
    wait current W/b READY
    for row_group in 0,4,...,96:
        reserve output block + snapshot
        for k in 0..63:
            acquire tagged X vector
            for g in 0..3:
                read W[nt+4*g : nt+4*g+4]
                issue valid lanes into acc[g]
        retire, finalize once, publish output block
    release weight slot only after all W/b references retire
all output handshakes complete -> core_done

双缓冲拆开：单W单Y → 双W单Y → 双W双Y。输出接收和输入供给须并发；接收器停顿不能覆盖输出，权重槽不能在偏置后处理仍引用时释放。

X4地址：bank=m%4, local=(m//4)*64+k。XP2地址：bank=m%2, local=(m//2)*64+k。W为四bank，块内bank=j%4, local=(j//4)*64+k。地址只是布局，不改变算子。

宏预算与逻辑容量分别记账，详情见docs/MEMORY_PORTS。大容量存储默认16位SP，一拍读或写；双向量保持、累加、控制等寄存器单列，不把所有小状态误算成必须16位SRAM，也不得遗漏其面积。

6. 新增XP2：认真利用“两块4096”的例子

2×4096×16可容纳一个99×64 INT16输入。两个存储体每拍只能给两个独立16位字，不能同拍直接给四行；但CTX4每个k使用一个四行向量四拍，因此可分两拍取齐四行，计算当前向量时预取下一向量。

采用两个向量保持槽，每槽4×16位，带k与row_mask。在默认1/2拍同步读延迟的抽象模型中，初始填充后可以每四拍交付一个新向量，不增加理想发射槽位。包内已做标签/端口/尾行/有限停顿的软件检查；这只证明该规格模型，不是新RTL时序。[D]

实施要求：先保持X4运行，单独改成XP2；记录X宏候选数、read命令、向量有效性、读在途数、等待周期和结果位真。较大读延迟无法隐藏时允许出现真实气泡，不改报表掩盖。宏面积/关键路径待指定库确认。

XP2只降低X存储体数。W仍每拍要四个独立权重，不能同样无分析地改成两个W存储体并声称吞吐不变。

7. 算子复用：现在设计边界，以后逐步实现

接受长期共享矩阵引擎的方向，但不把当前完整FP32编码器全删掉。下层分为：乘加原语、未截断部分和、地址/维度调度、末端数值处理；以后算子通过不同描述符使用它。

当前只启用K=64。将来QK是K64、P×V是K99、FFN2是K256，最后一个维度和输入类型也不相同；不能把dot64最终sat32输出直接相加实现更长点积。分段时部分和不清零、不加偏置、不舍入、不饱和，只在最终段后处理。具体反例和阶段门见docs/REUSE_ROADMAP。

FP32保留为扩展验证基线。未来本科top只例化选定整数核及其接口，不包括完整FP32编码器和旧V0重复硬件；源码保留不影响这个选择。整SoC功耗仍需按实际配置包含CPU/互连/共享SRAM。[S01][S10]

8. 逻辑接口、事件提交与死锁防线

继承RevC的一个有序事件输入流和一个独立结果流，不逐元素等待应答。入口接受、RAM写入、TILE_COMMIT退休、START退休分别计数。COMMIT不能越过尚未完成的写入。

V2主机/TB合法顺序固定：只预载tile0，然后START，再允许装后续tile。若在尚未START时排入一个需要等计算释放槽位的未来OPEN，该OPEN可能挡住后面的START；明确拒绝这种顺序或在源端禁止入队。V1全缓存装载不受这个分块槽位规则约束。

每笔输出有task_id、y_index=m*256+n、data、flags、last。核心输出可以按tile顺序，未来适配层按索引写正确地址。不得要求核心提前带MMIO地址，不为旧ROW_READY额外保存四行完整输出。

core_done只在全部25344个唯一有效结果实际握手后出现。未来system_done还必须等最后共享写响应。故障锁存且本任务作废；尚未握手的valid/payload稳定至接收或复位，不得假成功。软件协议模型不能替代RTL的时序和X状态测试。[W04]

SRAM：容量、端口、预取和生存期必须同时成立

1. 对用户评估中具体例子的核对

一个99×64 INT16张量有6336个16位元素，12672 B。两个16×4096宏共8192个元素，16384 B；容量足够，这一点是对的。

它没有证明四件事：四行每拍是否可同取；X与Y是否同时驻留；旧值是否还有残差/注意力用户；整个编码器的K/V/hidden/权重是否也装得下。

本科输出是99×256 INT32，即101376 B，不能直接按输入INT16体积来估计。[S01][S05]

完整编码器若所有X/Y/K/V都已另行证明可以INT16，并分别整张驻留，仅四者的有效数据就有50688 B。若每张都用两个4096宏，则分配65536 B、八个宏；还未含权重、行缓存、residual保留、flags和控制。不能把两宏容量结论外推到整个编码器。

2. X4默认布局

四bank：bank=m%4; addr=(m//4)*64+k。每bank按25×64=1600词分配，最后的不存在行由mask屏蔽。

每bank两颗1024深度宏串深度得到2048词；四bank总8宏、16 KiB。两颗串深度用于扩容，任何一拍同一bank仍只执行一次读或写，不会凭深度拼接增加并行端口。

容量更紧的组合是每bank1024+5×128=1664词：总24宏、13 KiB。它容量更小，但不保证面积更小，因为宏外围电路、译码、选择和布线都变化。没有宏面积资料时不选“最低字节=最低面积”。

也可每bank一颗4096：4宏、32 KiB。它宏个数少但浪费容量更多。容量、宏数、面积是不同目标。

3. XP2为什么值得增加为候选

XP2把X按行号奇偶放入两个4096深度SP存储体：

bank=m%2; addr=(m//2)*64+k

对四行组m0..m0+3，读取分两批：

预取批次 bank0 bank1
0 第m0行、k 第m0+1行、k
1 第m0+2行、k 第m0+3行、k（无效时屏蔽）

m0是4的倍数，所以该布局没有同拍同bank冲突。bank0最多3200词，bank1有效3136词，统一按3200词预算均放得进4096。

若是基础micro每拍都换一个k，就不能靠这两个读bank直接维持同样的四行吞吐。但CTX4每个k计算四组输出通道，保持当前X四拍，给预取下一k留下窗口。因此“容量够但端口少”不是永久否决，需要结合时分复用来分析。

两个4×16位向量寄存器分别保存当前向量和预取向量，共16 B；还需k、row_mask、返回有效掩码和在途计数。所有RAM返回均带槽位和身份，不使用当拍已经前进的k解释旧数据。[D]

在抽象模型的定义下，同步读延迟1/2拍、两个bank各每拍读一词，可在初始填充之后每4拍开始一个新向量。模型中W供数、MAC反馈和后处理尚未加入，不能把该周期直接写入“新版芯片延迟”。实际RTL必须重新验证相同事件顺序。

较长延迟或下游停顿可能引入气泡，有限停顿必须保持正确。必须为已发出的读预留返回空间；不能ready一撤就丢掉以后两拍才回来的RAM数据。

4. 主X bank读取数与宏数是两回事

micro→CTX4把X标量读取405504降到101376，是75%减少。

CTX4 X4→XP2仍是101376次标量读取，没有继续减少；它把同一向量读取分两拍，并允许更少独立存储体/宏。不能把75%再套一次，也不能据宏个数说节能75%。

一种大容量宏候选账本：

项目 X4 XP2
X 8个16×1024 2个16×4096
双W，4bank/槽、256词/bank 16个16×128 相同
双Y，4×16×32位/槽 4个16×128 相同
大容量宏总数 28 22
分配容量合计 21 KiB 21 KiB

此表不含bias、flags、部分和/快照、FIFO、控制寄存器，也不含宏选择译码和握手逻辑。它不提供mm²、工艺节点或功耗。bias/flags用寄存器还是指定小宏，后续按接口与面积资料选定并列入预算。

5. 生存期验收

X在一个本科任务内保留，跨正式任务清有效性并重装。W/b当前槽在最后偏置后处理退休之前不能释放。Y槽要等最后有效结果握手，快照也要有独立所有权。

完整编码器阶段，当前层输出成为下一层输入，是在完整attention/残差/LN/FFN都完成之后；独立FFN1的99×256输出绝不是下一层99×64输入。为减少写回不能覆盖仍有消费者的X、K、V或残差源。

6. 后续真实宏适配清单

核实宏名/引脚、时钟沿、CE/WE极性、byte mask、SP/DP语义、read-during-write、读延迟、输出保持、PVT角和面积/功耗。当前用不清零的大容量同步行为模型验证协议；没有对应lib和面积值时字段必须为null/待验，不得为0。

长期算子复用与混合精度路线（非本轮必做）

1. 不用“全删FP32”替代架构设计

当前FP32编码器是可复核的功能基线，值得保留。赛题允许浮点、定点或混合精度。[S01]

本科提交可以选择只实例化整数FFN1，新build profile排除FP32硬件，但保留其源码/参考/历史测试。面积统计看最终可达硬件，不看仓库文件有多少；未启用模块若仍被保留在网表里，就不能从预算中扣除。[S10]

若以后扩完整编码器，先复用矩阵乘加，再逐个处理非线性。允许保留小型浮点辅助单元处理敏感环节；最终是否全定点由整模型精度和PPA对照决定，不以“FP32天然不合规”为前提。

2. 真正可以共享的部分

运算 数学形式 归约长度K 与当前FFN1的新增差异
Q/K/V与输出投影 99×64乘64×64 64 输出维数、bias可选和矩阵布局
FFN1 99×64乘64×256 64 当前必做范围
QK转置 99×64乘64×99 64 转置访问、N=99尾列、attention缩放
P乘V 99×99乘99×64 99 概率数据类型/尺度、K尾段35
FFN2 99×256乘256×64 256 四个K64分段、激活格式变化

当前RevD engine仍仅支持K64、N为16倍数。上表说明将来必须新增什么，不表示现有脚本已经支持上述所有算子。

公共原语应返回“未完成后处理的宽部分和”，调度器带first_segment、last_segment、有效K、输出坐标；最后一段才加bias和做格式转换。权重、激活、probability不一定同号/同尺度，不能只把16位总线接上就认为数值一致。

3. 为什么不能拼接dot64的sat32输出

例如K256：前64项为32767×32767，第二64项为32767×(-32766)，后128项为0。正确未截断总和是2,097,088；若前两个64点积分别先sat32再相加，得到-1。即使每段dot64单独正确，整个长点积仍错。

又如K99，只有第0项为1、第64项为2，最终右移2位：正确RNE(3/4)=1；分别对两段做RNE得到0+0=0。

包内segmented_reference.py及单测验证这些反例，它们只是未来接口的数值说明，未修改当前硬件K64范围。

4. 精度演进步骤

E0：保持官方TensorFlow浮点参考与旧FP32 C参考。分别核对官方误差和本设计位真，不能混用。

E1：只在软件中，把某一类Dense运算替换为INT16×INT16宽累加。为每层记录X/W/b/输出scale、舍入、饱和、参考RMS、SSE。只用训练划分做无梯度标定；验证划分评估，测试集不调参数。

E2：先验证一个算子，再单层，再完整12层。所有中间张量有限，按原PostNorm顺序；残差两支必须先对齐实数尺度。

E3：矩阵路径通过后逐个试GELU、exp、reciprocal、rsqrt。非线性可以LUT/PWL/迭代，但要规定输入范围、截断、scale、系数精度、误差和周期，不能写一句“LUT加移位”就当完成。

E4：再比较W8/X16与W16/X16，逐通道尺度是否增加额外乘法/读带宽。不同配置不混拼效率结果。

E5：新参考→组件RTL位真→单层/12层位真→正式精度条件→PPA。满足后选最终profile，旧FP32继续归档。

5. 非线性易错点

Softmax需保持减最大值、exp非负、分母不为0、输出有限以及归一化误差可控；分母通常不是2的整数幂，不能一般化成右移。

LayerNorm除以D=64可与二幂比例有关，但rsqrt(var+epsilon)仍不是简单移位。方差累加可能需要更宽整数；epsilon必须进入正确尺度，不能量化成0导致常数向量故障。

GELU需区分官方erf形式、当前tanh型近似及新LUT/PWL；不能把对近似C零位差称为对官方模型零误差。[S07][S11]

6. E203和时序边界

现在仅稳定逻辑流。后续先沿已验证ICB路径接真实E203，再根据平台主端口决定DMA；不宣称已有NICE硬件。FP32的FMA组合快路径有待STA的风险，但除法/开方已多周期；管线化或混合精度都是可评估选项，不是唯一的“淘汰”路径。[S06][W01]

数值精度：保持正确性，还要保留得分余量

来源是用户上传指南，不把以下示例当正式成绩。[S01]

1. 本科NRMSE

每层汇总所有样本的全部输出元素后，计算：

NRMSE = sqrt(sum(error²)/N) / max(sqrt(sum(reference²)/N), 1e-8)。

最后取12层最大值。不能平均每个样本的NRMSE，因为参考能量不同。正式12个性能任务还须分别满足3%门槛。

以比例r表示误差：精度分为max(0, 10-r/0.003)。例如0.003是0.3%，得9分；0.03是3%，得0分。不能把3%叫满分精度线。

更低的内部目标可以提高得分余量，但属于工程选择而非官方新增门槛。当前结构优化保持完全相同的数值合同，必须零位差，不能用NRMSE容差掩盖RTL错误。

2. 研究生Top-1

使用同一数据集与同一分类头：drop_pp = 100*(reference_correct - candidate_correct)/sample_count。

准入要求drop_pp≤2，精度分为clip(10-drop_pp/0.2,0,10)。570/600降至558/600是下降2个百分点，不是相对下降2%；该项得0分但恰在数值门槛。

precision_metrics.py用整数计数/Fraction进行Top-1边界判断，避免二进制浮点把精确的2个百分点误判为大于2。

3. 分离数值阶段和架构阶段

架构A/B只改变并行调度/缓存，不改变X/W/b/scale/shift，参考输出应一样。INT8/逐通道/非线性替换另开数值配置，先软件评估。不同数值配置的精度、时延、功耗必须完整绑定，不拼接最优结果。

模型来源是指定TensorFlow实现及权重。Python定点参考不是用gcc编译的；C参考的禁止自动收缩与显式fmaf同时存在，保持既定操作顺序。[S04][S05][S07][S08]

4. 数据集使用

训练划分：无梯度标定。验证划分：调试与精度验证。测试划分：不得用于调权重、量化参数或配置。记录样本身份、划分、选取规则、原始数据及提取数组摘要。

本轮路线

D0固定契约和复现；D1基础micro；D2全缓存矩阵；D3CTX4；D4单W/Y；D5分别双W/双Y；D6可选XP2；D7同条件比较。

4×4为主，2×4对照；K64、N16..256且16倍数，M1..99，N_TILE16。数值保持signed16乘、signed48累加、signed49加bias、sat48、RNE、sat32和原flags。所有shift0..47、极值、最后乘积及连续任务/复位都要测试。

CTX4每k读取保持四行X，按四个列组更新四上下文。向量/acc/快照/输出都带标签和owner；反馈延迟与返回信用要按真实时序验证。

V2外层按16列W块，内层处理全部99行，每W/b每任务只装一次。大bank为16位单端口同步读，不清零RAM。W在最后bias使用结束前不释放；Y在最后结果握手前不覆盖。

新增XP2不是默认替换X4。两个16×4096候选存储体按m%2放X，四行分两拍读，CTX4四组计算期间预取下一k；保留两组向量寄存器。比较1/2拍RAM延迟，不能只凭容量足够说带宽足够，不能把22vs28个宏写成确定面积节省。

公开逻辑接口

使用一个有序事件流BEGIN/LOAD_X/TILE_OPEN/LOAD_W/LOAD_B/TILE_COMMIT/START，正常数据不逐元素应答。入口接受与实际RAM写入分开，COMMIT/START不可越过未完成写。

V2只在START前预载tile0；不得让一个等EMPTY槽的未来OPEN阻塞队列中后续START。输入供给和输出接收必须并发。未取得slot是合法背压，非法顺序是错误；不要用全局大超时掩盖死锁。

结果带task_id、y_index、data、flags、last。25344个唯一有效输出被真正接受后才core_done，未来system_done另等共享写响应。故障不假成功，valid背压保持至握手或reset。

TB可以从公开端口装载输入并接结果。禁止直写DUT私有RAM、内部强制状态、答案回灌或CPU软件代算必做运算。旧数值模型为golden，新软件模型只辅助。
