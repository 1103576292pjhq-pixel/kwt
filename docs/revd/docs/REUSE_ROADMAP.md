# 长期算子复用与混合精度路线（非本轮必做）

## 1. 不用“全删FP32”替代架构设计

当前FP32编码器是可复核的功能基线，值得保留。赛题允许浮点、定点或混合精度。[S01]

本科提交可以选择只实例化整数FFN1，新build profile排除FP32硬件，但保留其源码/参考/历史测试。面积统计看最终可达硬件，不看仓库文件有多少；未启用模块若仍被保留在网表里，就不能从预算中扣除。[S10]

若以后扩完整编码器，先复用矩阵乘加，再逐个处理非线性。允许保留小型浮点辅助单元处理敏感环节；最终是否全定点由整模型精度和PPA对照决定，不以“FP32天然不合规”为前提。

## 2. 真正可以共享的部分

| 运算 | 数学形式 | 归约长度K | 与当前FFN1的新增差异 |
|---|---|---:|---|
| Q/K/V与输出投影 | 99×64乘64×64 | 64 | 输出维数、bias可选和矩阵布局 |
| FFN1 | 99×64乘64×256 | 64 | 当前必做范围 |
| QK转置 | 99×64乘64×99 | 64 | 转置访问、N=99尾列、attention缩放 |
| P乘V | 99×99乘99×64 | 99 | 概率数据类型/尺度、K尾段35 |
| FFN2 | 99×256乘256×64 | 256 | 四个K64分段、激活格式变化 |

**当前RevD engine仍仅支持K64、N为16倍数。**上表说明将来必须新增什么，不表示现有脚本已经支持上述所有算子。

公共原语应返回“未完成后处理的宽部分和”，调度器带first_segment、last_segment、有效K、输出坐标；最后一段才加bias和做格式转换。权重、激活、probability不一定同号/同尺度，不能只把16位总线接上就认为数值一致。

## 3. 为什么不能拼接dot64的sat32输出

例如K256：前64项为32767×32767，第二64项为32767×(-32766)，后128项为0。正确未截断总和是2,097,088；若前两个64点积分别先sat32再相加，得到-1。即使每段dot64单独正确，整个长点积仍错。

又如K99，只有第0项为1、第64项为2，最终右移2位：正确RNE(3/4)=1；分别对两段做RNE得到0+0=0。

包内`segmented_reference.py`及单测验证这些反例，它们只是未来接口的数值说明，未修改当前硬件K64范围。

## 4. 精度演进步骤

E0：保持官方TensorFlow浮点参考与旧FP32 C参考。分别核对官方误差和本设计位真，不能混用。

E1：只在软件中，把某一类Dense运算替换为INT16×INT16宽累加。为每层记录X/W/b/输出scale、舍入、饱和、参考RMS、SSE。只用训练划分做无梯度标定；验证划分评估，测试集不调参数。

E2：先验证一个算子，再单层，再完整12层。所有中间张量有限，按原PostNorm顺序；残差两支必须先对齐实数尺度。

E3：矩阵路径通过后逐个试GELU、exp、reciprocal、rsqrt。非线性可以LUT/PWL/迭代，但要规定输入范围、截断、scale、系数精度、误差和周期，不能写一句“LUT加移位”就当完成。

E4：再比较W8/X16与W16/X16，逐通道尺度是否增加额外乘法/读带宽。不同配置不混拼效率结果。

E5：新参考→组件RTL位真→单层/12层位真→正式精度条件→PPA。满足后选最终profile，旧FP32继续归档。

## 5. 非线性易错点

Softmax需保持减最大值、exp非负、分母不为0、输出有限以及归一化误差可控；分母通常不是2的整数幂，不能一般化成右移。

LayerNorm除以D=64可与二幂比例有关，但rsqrt(var+epsilon)仍不是简单移位。方差累加可能需要更宽整数；epsilon必须进入正确尺度，不能量化成0导致常数向量故障。

GELU需区分官方erf形式、当前tanh型近似及新LUT/PWL；不能把对近似C零位差称为对官方模型零误差。[S07][S11]

## 6. E203和时序边界

现在仅稳定逻辑流。后续先沿已验证ICB路径接真实E203，再根据平台主端口决定DMA；不宣称已有NICE硬件。FP32的FMA组合快路径有待STA的风险，但除法/开方已多周期；管线化或混合精度都是可评估选项，不是唯一的“淘汰”路径。[S06][W01]
