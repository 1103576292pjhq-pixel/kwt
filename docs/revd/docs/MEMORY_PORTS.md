# SRAM：容量、端口、预取和生存期必须同时成立

## 1. 对用户评估中具体例子的核对

一个99×64 INT16张量有6336个16位元素，12672 B。两个16×4096宏共8192个元素，16384 B；**容量足够，这一点是对的**。

它没有证明四件事：四行每拍是否可同取；X与Y是否同时驻留；旧值是否还有残差/注意力用户；整个编码器的K/V/hidden/权重是否也装得下。

本科输出是99×256 INT32，即101376 B，不能直接按输入INT16体积来估计。[S01][S05]

完整编码器若所有X/Y/K/V都已另行证明可以INT16，并分别整张驻留，仅四者的有效数据就有50688 B。若每张都用两个4096宏，则分配65536 B、八个宏；还未含权重、行缓存、residual保留、flags和控制。不能把两宏容量结论外推到整个编码器。

## 2. X4默认布局

四bank：`bank=m%4; addr=(m//4)*64+k`。每bank按25×64=1600词分配，最后的不存在行由mask屏蔽。

每bank两颗1024深度宏串深度得到2048词；四bank总8宏、16 KiB。两颗串深度用于扩容，任何一拍同一bank仍只执行一次读或写，不会凭深度拼接增加并行端口。

容量更紧的组合是每bank1024+5×128=1664词：总24宏、13 KiB。它容量更小，但不保证面积更小，因为宏外围电路、译码、选择和布线都变化。没有宏面积资料时不选“最低字节=最低面积”。

也可每bank一颗4096：4宏、32 KiB。它宏个数少但浪费容量更多。容量、宏数、面积是不同目标。

## 3. XP2为什么值得增加为候选

XP2把X按行号奇偶放入两个4096深度SP存储体：

`bank=m%2; addr=(m//2)*64+k`

对四行组m0..m0+3，读取分两批：

| 预取批次 | bank0 | bank1 |
|---|---|---|
| 0 | 第m0行、k | 第m0+1行、k |
| 1 | 第m0+2行、k | 第m0+3行、k（无效时屏蔽） |

m0是4的倍数，所以该布局没有同拍同bank冲突。bank0最多3200词，bank1有效3136词，统一按3200词预算均放得进4096。

若是基础micro每拍都换一个k，就不能靠这两个读bank直接维持同样的四行吞吐。但CTX4每个k计算四组输出通道，保持当前X四拍，给预取下一k留下窗口。**因此“容量够但端口少”不是永久否决，需要结合时分复用来分析。**

两个4×16位向量寄存器分别保存当前向量和预取向量，共16 B；还需k、row_mask、返回有效掩码和在途计数。所有RAM返回均带槽位和身份，不使用当拍已经前进的k解释旧数据。[D]

在抽象模型的定义下，同步读延迟1/2拍、两个bank各每拍读一词，可在初始填充之后每4拍开始一个新向量。模型中W供数、MAC反馈和后处理尚未加入，不能把该周期直接写入“新版芯片延迟”。实际RTL必须重新验证相同事件顺序。

较长延迟或下游停顿可能引入气泡，有限停顿必须保持正确。必须为已发出的读预留返回空间；不能ready一撤就丢掉以后两拍才回来的RAM数据。

## 4. 主X bank读取数与宏数是两回事

micro→CTX4把X标量读取405504降到101376，是75%减少。

CTX4 X4→XP2仍是101376次标量读取，没有继续减少；它把同一向量读取分两拍，并允许更少独立存储体/宏。不能把75%再套一次，也不能据宏个数说节能75%。

一种大容量宏候选账本：

| 项目 | X4 | XP2 |
|---|---|---|
| X | 8个16×1024 | 2个16×4096 |
| 双W，4bank/槽、256词/bank | 16个16×128 | 相同 |
| 双Y，4×16×32位/槽 | 4个16×128 | 相同 |
| 大容量宏总数 | 28 | 22 |
| 分配容量合计 | 21 KiB | 21 KiB |

此表不含bias、flags、部分和/快照、FIFO、控制寄存器，也不含宏选择译码和握手逻辑。它不提供mm²、工艺节点或功耗。bias/flags用寄存器还是指定小宏，后续按接口与面积资料选定并列入预算。

## 5. 生存期验收

X在一个本科任务内保留，跨正式任务清有效性并重装。W/b当前槽在最后偏置后处理退休之前不能释放。Y槽要等最后有效结果握手，快照也要有独立所有权。

完整编码器阶段，当前层输出成为下一层输入，是在完整attention/残差/LN/FFN都完成之后；独立FFN1的99×256输出绝不是下一层99×64输入。为减少写回不能覆盖仍有消费者的X、K、V或残差源。

## 6. 后续真实宏适配清单

核实宏名/引脚、时钟沿、CE/WE极性、byte mask、SP/DP语义、read-during-write、读延迟、输出保持、PVT角和面积/功耗。当前用不清零的大容量同步行为模型验证协议；没有对应lib和面积值时字段必须为null/待验，不得为0。
