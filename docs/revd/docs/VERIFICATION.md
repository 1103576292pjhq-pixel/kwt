# 验证、对照实验与失败标准

## 1. 从哪些证据开始

先核对原基线，不改动原数值格式。源码事实参见S5；RevC软件模型采用同一书面规则，但本包没有执行旧V0文件。实际开发时使用 `tools/compare_v0.py` 核对固定blob，随后才把原36个工程案例作为硬件回归输入。

文件对照至少分三层：独立稠密参考、候选CTX4软件循环、真实RTL公开结果。前两层相同不等于第三层正确。不要让TB通过新RTL调度函数生成自己的“期望地址”，否则同一地址错误可能被两边同时复制。

## 2. 数值和几何

- 对合法int16极值、全零、抵消、只有k=63非零、bias端点、shift0..47、正负半值取偶数、raw48溢出与int32饱和分别测试。
- 同一输出的64项仍按k递增。CTX4每条乘积带g标签直到退休，检测g错位、漏末项、下一块acc清零覆盖旧快照。
- engine支持N为16的整数倍。M测试1、3、4、5、99，N测试16、32、256，PM测试1、2、4，共45组几何。N=17/255、K≠64、PM=3、N_TILE≠16必须拒绝。
- 生产几何覆盖第0/15/16/255列和第0/95/96/98行。M=99时屏蔽最后一个lane，不读初值未知的填充行。

## 3. 背压、所有权和结束

必须测试输出valid已有数据时ready突然拉低、上下文中间g停顿、RAM1/2拍仍有返回、结果FIFO满、最后输出长期但有限阻塞、W_READY迟到、COMMIT早于真实写入、错误tile/重复index、reset打断。

结果必须包含M*N个唯一index、正确task_id、正确data/flags、严格发布次序和恰好一个末条last。固定比较顺序并不取消唯一性检查。

TB源必须独立消费输出；不能先堵塞在“把全部下一块写完”，再开始读出结果，因为DUT本来需要输出空间才继续释放资源。对源/汇公平性给出有界约束，例如最大连续停顿不超过128拍。无限背压下不能要求固定周期内必然done。

## 4. 包内软件负测与未来RTL变异

本包已包含14个可检测的错误变异/负测实例：改变结果/flags/task/index/last/类型/顺序、缺失或多出结果，以及漏最后乘积。它们是在软件模型与文件scoreboard上触发，不是已跑RTL变异。

未来RTL需要至少可编译地注入以下错误并观察测试失败：
1. 漏k=63；2. signed变unsigned；3. 使用当拍g而不是流水g；4. 偏置饱和与舍入交换；5. 输出未握手就回收Y槽；6. COMMIT忽略pending write；7. W槽提前释放；8. 复位不清一条valid。

## 5. 七组同条件配置

| 配置 | 目的 |
|---|---|
| p0_v1_pm2_micro | 8 MAC低并行度基线 |
| p1_v1_pm4_micro | 16 MAC基础调度 |
| p2_v1_pm4_ctx4 | 只改变输入保持/部分和上下文 |
| p3_v2_w1_y1 | 在CTX4基础上只改W容量/分块 |
| p4_v2_w2_y1 | 只增加W预取重叠 |
| p5_v2_w2_y2 | 再增加Y排出重叠 |
| p6_v2_pm2_w2_y2 | 同搬运方式的8 MAC候选 |

配置文件中写 `implementation_status=PLAN_ONLY`，不是RTL运行记录。软件分析器不会据此创建任何RTL。

对照时固定输入、数值、RAM延迟、源汇节奏、工具及窗口。CTX4的X向量寄存器、更多acc和快照都计入逻辑资源，不能只列降低的SRAM访问。

## 6. 时间窗口与计数

解析发射槽位和真实RTL周期分开；全缓存START前装载与分块START后预取不同，因此不能只比较START到done就断言整任务谁更快。首LOAD_X到末输出窗口包含当前逻辑接口下的数据装载，但仍未包含E203指令、共享端仲裁和系统写回，故不得命名为SoC端到端。

主X/W读取预测必须用DUT实际RAM CE及地址检查，连续读取同一个地址也算一次读。CTX4保持寄存器的读和选择网络活动另计；少读75%主X不是“总动态功耗少75%”。

物理吞吐量必须有实际工作频率，150MHz时序未签核之前，不把行为时钟参数当作频率结论。工艺指标本轮NOT_RUN。

## 7. 运行记录与证据新鲜度

每个运行独立目录，记录源码文件及未提交新文件SHA、配置、参考SHA、输入SHA、工具版本、实际命令、退出码、开始/结束时间、输出数、首个失败、日志和波形索引。新代码未提交时，仅记录旧HEAD不够。

旧36案例属于工程样本，不是正式600样本。任何扩大覆盖用验证划分，标定只能训练划分。不得按测试集结果调量化配置。[S8]

遇到缺模拟器、编译失败、超时、少输出、未知值、SKIP和子进程失败，标注具体失败或NOT_RUN，不修饰成PASS。独立复跑是新进程，不是把同一文件再读一次。

## 8. 本包工具的边界

`self_check.py`：标准库软件测试。
`analyze.py`：理想发射和逻辑读取/容量算式。
`export_vectors.py`：生成合成组件输入/参考，不能替代原官方权重数据。
`scoreboard.py`：比较真实输出记录文件；文件匹配不证明来源新鲜。
`repo_preflight.py`：只读查本地关键文件，不执行代码、不运行仿真，不代替原仓库完整性检查。
`compare_v0.py`：仅在用户本地明确调用后执行指定blob的可信V0源码，依赖NumPy；本包未运行。
`verify_package.py`：核对未签名manifest，非硬件验收。

## RevD新增验收

增加X4/XP2同数据对照，覆盖1/2拍读延迟、尾行和输出停顿；软件预取模型只检查规格而非RTL时间。增加容量/宏个数/面积未知分离、NRMSE聚合与评分例子、分段点积中间舍入/饱和/重复bias的错误反例。当前K64硬件范围不扩成K99/256。

D4/D5须另在真实RTL测试V2未来OPEN挡住START的队首等待风险；本包新增软件单测未宣称覆盖完整流式RTL状态机。源码审查、模型测试和真正新RTL运行分别计数。
