# KWT 下一版优化计划 RevC

版本：2026-10-17。对象：本科FFN1独立加速器。性质：**设计决策、开发执行书和软件校核工具**，不冒称已经实现新硬件。

## 1. 先固定方向，而不是再次扩张工程

保留RevB的主线：V0作为数值和功能基准，先完成独立计算核，再接E203，最后逻辑综合与规定指标评估。本轮不开发ICB桥、PIO固件、DMA、NICE、CPU/SoC仲裁、工艺映射，不安装PDK，也不等待正式宏库。[S1]

KWT基线固定 `3d9d0fc77457b8869cbf525d826dafb114f2a8e1`；E203开发参考固定 `9f3e34f337f5d0a1236a285871ffa2032491617a`。KWT main本次读取仍为所列提交。E203在本轮仅作为未来外层接口参考，不把其时钟/外设示例当成已经实现比赛配置。旧vendor、CPU封装、旧驱动、数值模型和历史证据不修改。[S2][S3][S4]

总体路线变为：

**基础4×4微阵列 → 相同16个MAC的CTX4复用候选 → 16列权重分块 → 单独增加双W和双Y → 固定版本比较 → 未来E203与综合。**

4×4仍是首选候选，2×4仍保留。未得到目标库结果之前，不认定哪一个是最终PPA最优。

## 2. 这次重新优化了什么

### 2.1 从“同一个X读四遍”改为“保持一次、使用四组”

RevB在4×16结果块内，先算完一个4×4小块的64项，再算下一个。这意味着同一组四行X会针对四个输出列组各读一遍。[S1]

RevC新增CTX4（四组部分和上下文）候选：仍只有16个乘法器，每个MAC保留四个48位累加槽。先取同一个k的四个X，再依次与四个列组的W相乘，分别更新对应累加槽，然后进入下一个k。

```
基础micro：
    for g in 0..3:
        for k in 0..63:
            读取X向量、读取W向量、更新第g列组

CTX4：
    for k in 0..63:
        读取并保持一个X向量
        for g in 0..3:
            读取W向量，更新acc[g]对应的列组
```

这是本轮提出的架构候选，不是声称FINN或E203已经包含此实现。它可以理解为在既有输出通道分组上移动循环层级，用额外局部部分和寄存器换取主X存储更少的读取。FINN中多向量、输出PE及累加数组提供了并行维度划分的参考，但不能直接把其HLS代码当作E203的SystemVerilog实现。[S6]

### 2.2 数学为什么不变

对固定输出(m,n)，CTX4仍按k=0、1、…、63顺序把同一对X/W加到该输出的累加槽。改变的是不同输出之间的穿插顺序，没有改变一个输出内部的累加顺序，没有改变bias、shift或饱和规则。

令n=nt+4g+c，则：

`acc[r,g,c] <- acc[r,g,c] + X[m0+r,k] * W[k,nt+4g+c]`

其中r=0..PM-1、g=0..3、c=0..3。尾部不存在的行不读、不写、不计有效MAC。四行仍是单个任务中的token，不是batch=4。

### 2.3 解析收益与额外代价必须一起列出

以下针对M=99、K=64、N=256、PM=4、PN=4、N_TILE=16，没有额外跨块寄存复用，采用单端口同步bank及有效行屏蔽。数据来自包内分析程序与功能循环计数，不是RTL仿真或芯片实测。

| 指标 | 基础micro | CTX4 |
|---|---:|---:|
| MAC数量 | 16 | 16 |
| 理想K/g发射槽位 | 102400 | 102400 |
| 有效MAC | 1622016 | 1622016 |
| 主X bank标量读取 | 405504 | 101376 |
| 主W bank标量读取 | 409600 | 409600 |
| 主X/W bank读取合计 | 815104 | 510976 |
| 48位部分和寄存器 | 96 B | 384 B |
| 一份同规模快照 | 96 B | 384 B |

主X读取减少75%，主X/W合计减少约37.31%。**这不是总存储访问减少37.31%，也不是功耗或时延改善37.31%。** CTX4增加累加上下文选择、寄存器读写和控制；若两种方案都保留一份快照，部分和+快照合计多576 B，还可增加两组X向量保持寄存器共16 B。面积、关键路径和能耗结论留到以后。

理想计算槽位没有减少。因此这项优化首先针对主存储读取，不承诺纯计算周期再提高四倍。若上下文选择导致更多停顿或控制风险，可保留基础micro作为正式候选，不影响前一阶段成果。

## 3. 数值与工程支持范围不再含糊

保持V0规则：[S5]

```
dot48 = sum(k=0..63, signed16(X) * signed16(W))
sum49 = sign_extend(dot48) + sign_extend(bias48)
raw48 = saturate_signed48(sum49)
rounded = round_to_nearest_even(raw48 / 2**shift)
y32 = saturate_signed32(rounded)
flags = {saturated, overflow}
```

合法输入端点是-32768和32767，不包含+32768。shift只允许0..47。先sat48，再RNE，再sat32，不能交换。64项最大乘积累加的绝对值不超过2^36，48位对点积本身有余量；bias相加仍要49位并按原规则饱和。

新参考脚本是包内校核模型，不能取代仓库冻结 `numeric/fixedpoint.py` 作为正式golden。实际开发先用 `compare_v0.py` 在本地核对指定blob，再把旧工程向量引入RTL测试。新布局只能改地址、调度和编码顺序，不能在输入适配器里代算必做矩阵。

首轮engine的支持范围固定为：M=1..99；N=16..256且是16的整数倍；K=64；PM∈{1,2,4}；PN=4；N_TILE=16；RAM读延迟先1拍、再验证2拍。不把N=17、255列为“应该能算但没验证”的模糊参数；这些配置必须明确拒绝。独立PE/microtile层仍可用行列mask测试局部尾数。完整赛题尺寸当然包含在内。

12层是12套各自提取的FFN1输入和参数，不把99×256输出直接喂给下一次99×64输入。每个独立任务重新装X/W/b，不靠跨任务缓存缩短冷启动窗口。[S8]

## 4. 当前数据通路

### 4.1 V1先做全缓存与基础调度

V1使用全部X、全部W缓存，避免第一步就调试预取。先实现 `mac_lane`、`micro_tile` 和 `quant_epilogue`，形成基础4×4路径；之后新增 `context_tile`，在相同全缓存条件下比较micro与CTX4。

后处理先不重叠，再加入快照与下一块重叠。CTX4的最后一笔有效乘积退休后，才允许快照完成的4×16部分和。快照要有独立容量和所有权，不允许下游停顿时被下一块覆盖。

每个MAC有四个局部寄存器槽，不要求一个SRAM同拍提供16组部分和访问。若把该小数组交给工具推断RAM，必须重新核对读延迟和反馈关系；本轮先把它作为明确的寄存器阵列实现并计数。

### 4.2 流水标签不能丢

至少随数据传递：task_id、row_group、k、g、first、last、valid、row_mask。上下文g必须从乘法发射一路跟到累加退休，不能使用当拍调度器已经前进的g。

同一acc[g]在CTX4中每4个成功发射槽位更新一次；真实流水反馈延迟仍须检查。最小版本采用一拍乘积寄存、下一拍加到寄存器，确保同一上下文回写先于下一次读取；未来增加流水深度时要加冒险检查或旁路，不能凭“隔四拍”假定永远安全。

四个列组还未全部接受X时，不得覆盖当前X保持寄存器。预取下一k可以使用另一组X寄存器，但要有明确valid和k标签。背压时所有未交付payload保持，状态只按fire推进。[S7]

## 5. V2权重分块与缓冲

V2保持全X驻留，外层先遍历16列权重块，内层遍历全部99行。CTX4在每个PM×16结果块内按k、g顺序计算。

```
装全部X；装tile0；提交tile0；START
for nt in 0,16,...,240:
    等当前W/b块READY
    for m0 in 0,PM,...:
        预留一个完整结果块和快照空间
        for k in 0..63:
            保持X[m0:m0+PM,k]
            for g in 0..3:
                读取四个W，发射PM×4次MAC
        退休全部乘积，快照并后处理，发布结果块
    确认所有W/b使用者释放后回收权重槽
结果全部实际交付后才core_done
```

一个权重块2 KiB，双权重块4 KiB；每个W和bias每任务只装一次。主配置逻辑容量：X12,800B、双W4,096B、双Y512B、bias192B、flags32B，合计17,632B；另计累加/快照768B、X保持16B、FIFO及控制。上述是逻辑数据容量，不是指定宏向上取整后的容量，更不是mm²。

X bank映射：`bank=m%PM; addr=(m//PM)*64+k`。
W全缓存：`bank=n%4; addr=(n//4)*64+k`。
W分块：`j=n%16; bank=j%4; addr=(j//4)*64+k`。

每个bank一拍读或写一次。RAM不整体复位，复位仅清有效性和所有权；最后虚拟行不读RAM。读延迟1或2拍均通过返回信用处理，不依赖“刚发地址就用到新数据”。

双缓冲必须拆开做：单W单Y → 双W单Y → 双W双Y。W槽只在所有权重和bias用户都完成后释放；Y槽只在最后一个结果被接收方握手接受后释放。详细接口与故障规则见 `docs/INTERFACE.md`。

## 6. 接口再简化：一个有序输入流，独立结果流

RevB分别列出了command/response和load/response，但未限定能否连续接收，存在把每个元素做成一来一回应答的风险。[S1] RevC把命令与数据编码在一个有序逻辑输入流里；短入口FIFO吸收背压，正常数据不要求逐元素响应。

事件包括：BEGIN、LOAD_X、TILE_OPEN、LOAD_W、LOAD_B、TILE_COMMIT、START。流中带任务/层号、逻辑tile_id、索引与数据，不带MMIO地址，也不暴露物理slot。

“已进入FIFO”和“真实写入RAM”分开计数。TILE_COMMIT必须在该块此前所有数据已写到存储后生效；START不能越过COMMIT。输出每笔带索引、数值、flags和last，按固定tile/row_group/row/column顺序发布，背压时不变化。

发生非法协议输入后锁存错误，本任务作废，不产生成功done；已经有效但未握手的结果保持到握手或复位，不能随意撤回valid。新任务必须复位恢复。合法OPEN只是暂无EMPTY槽时可以等待，不等于故障。没有必要在本轮实现复杂的软重试/中断/总线abort。

状态读取不阻塞计算和供数；core_done只表示全部输出从核心交付，不等于未来共享SRAM写回完成。

## 7. 验证放到开始，不再等R3才补

入口稳定性、同步RAM返回信用、输出唯一性和复位测试从第一笔微块就加入。验证分成数值模型、协议规格模型、真实RTL三个层级；软件规格模型通过不能升级成RTL通过。

采用“双参考”避免自证：旧冻结V0作为正式数值基准；包内独立Fraction参考与整数CTX4循环作为辅助交叉检查。包内scoreboard拒绝重复、缺失、越界、任务错误、flags错误、顺序错误和last错误；比较文件本身不证明那个文件真由RTL产生。

新RTL每次运行必须记录真实仿真命令、源码及未提交文件摘要、实际消费的输入、工具版本、退出码、输出完整数量和首个失败点。阶段状态必须有范围，不把总计划、工具自测或旧PASS作为新硬件验收。

## 8. 开发阶段与退出条件

| 阶段 | 做什么 | 结束后必须拿到什么 |
|---|---|---|
| C0 | 固定基线、先跑软件/旧数值对照；定义接口 | 可复现配置和明确未运行项 |
| C1 | 基础4×4微阵列+后处理+最小握手 | 48种shift、极值、末项、背压、复位短测 |
| C2 | 全缓存V1，固定输出顺序 | 小矩阵→一个全尺寸→旧36案例→独立复跑 |
| C3 | 同缓存、同阵列加入CTX4 | 位真一致；X/W读取计数与解析值吻合 |
| C4 | CTX4改为单W块、单Y块 | 完整任务不重复装W/b；减少W容量 |
| C5 | 分别加双W、双Y | 所有权、末bias引用、返回信用与停顿测试 |
| C6 | PM2/4与七组配置对照、冻结 | 核心数据结论，不声称SoC或PPA达标 |

C0—C6不依赖正式工艺库。不要同时启动完整编码器或CPU大回归。任何阶段失败先修，不能继续堆功能取得更多表面覆盖。

## 9. 公平对照与计时

七组配置文件分别覆盖：V1_PM2_micro、V1_PM4_micro、V1_PM4_CTX4、V2_W1Y1、V2_W2Y1、V2_W2Y2、V2_PM2_W2Y2。

对比micro和CTX4时先保持full缓存及相同结果块；对比full和tiled时保持CTX4与源汇节奏；对比单双缓冲分别只改一个槽数。不把所有改动一次做完，再把全部收益归给某一种算法。

记录三层数量：数学有效MAC=1,622,016；有效乘积/退休事件实际计数；无效lane槽位=16,384（主配置）。TB观察真实fire和CE事件，不直接把固定公式输出到报告冒充观测。

记录 `ideal_issue_slots`（解析）、`issue_count`（真实发射）、`core_run_cycles`（START退休到末输出握手，首末拍都计入）、`frontend_cycles`（首LOAD_X握手到末输出握手，首末拍都计入）。二者不是未来E203端到端周期。full与tiled的START前装载不同，因此跨版本总比较优先frontend窗口，core_run仅解释内部停顿。

互斥停顿分类按固定优先级：fatal > 等W > 等结果空间 > 等读返回/操作数 > 发射/退休工作 > 收尾。并发活动计数另列，不把重叠事件相加当总周期。

本轮TB使用逻辑元素供数：源gap、汇ready设1/2/4/8/16及有界随机停顿。先独立源/汇，再可选一个共享服务预算模型；它们都不是E203实测。双缓冲只隐藏等待，不增加带宽。最后一个Y槽排出、最后快照退休都必须计时。

## 10. 后续与E203的接合点

E203上游子系统具有sysper/sysmem请求响应接口，KWT已有薄封装；本轮核保持单时钟和不含总线地址的接口，未来可在外层翻译成ICB控制与数据事务。[S3][S4]

V3先按既有E203框架实现真实PIO适配、共享存储写回和system_done；之后再决定DMA，不能把sysper从端口误当成能够直接读共享存储的主端口。NICE本轮不做。时钟、复位、共享地址及完整比赛平台差异在该阶段重新核对。

V4才做指定库/宏映射、SDC、STA、综合网表、面积与功耗、综合后验证，满足150MHz及2.25mm²等正式条件。此顺序不取消比赛必做，只是不拿它阻塞独立核优化。[S8]
