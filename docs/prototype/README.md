# FFN1 原型：从整数到矩阵调度

这批实现把一个可复核的整数线性层变成真实 RTL：输入经公开端口写入同步存储，单个乘法器完成点积，输出逐行交给读取方。先跑通，再沿“数值 → DOT64 → 存储 → 调度 → 验证”阅读。

| 模块 | 输入 | 处理 | 输出 | 阅读入口 |
|---|---|---|---|---|
| 定点转换 | 冻结的 float X/W/b | 固定输入尺度、逐层权重范围、RNE 编码 | 整数向量、配置、误差 | [numeric](../../numeric/README.md) |
| DOT64 | 64 对 int16、int48 bias、shift | 单 MAC、48 位累加、49 位加偏置检查、RNE/sat32 | int32、raw48、两个范围标记 | [RTL](../../rtl/dot64.sv)、[协议](../../dv/dot64/README.md) |
| 同步存储 | 装载写入或内部读地址 | 上升沿写入或读出，读写分时 | 下一拍可用的数据寄存器 | [RAM wrapper](../../rtl/prototype_sync_ram.sv) |
| FFN1 | 当前一套 X/W/b | m/n/k 遍历、预取、逐行缓冲 | ROW_READY、读回、ACK、DONE | [RTL](../../rtl/ffn1_top.sv)、[接口](interface.md) |
| 证据门禁 | XML、向量、RTL 输出和哈希 | 拒绝缺例、跳过、错误或过期证据 | READY_FOR_REVIEW 或非零退出 | [验证说明](verification.md) |

数据链为：冻结 float 案例 → 确定性整数编码 → 公开装载 X/W_pack/b → 同步读 → 64 次乘加 → 偏置与舍入饱和 → 行缓冲 → 公开读回 → ACK → 逐位比对与哈希复跑。

## 1. 先理解每一个整数代表什么

量化整数只是数值编码，必须与尺度一起解释。固定输入步长为 $s_x=2^{-8}$，$Q_x=\operatorname{sat}_{16}(\operatorname{RNE}(X/s_x))$。每层从完整冻结 W 的最大绝对值计算能覆盖其范围的最小二幂 $s_w$，不使用样本输出选择尺度。$Q_w$ 与 $Q_b$ 分别采用 $s_w$ 与 $s_xs_w$ 编码。

对一个输出，RTL 先算

$$a=\sum_{k=0}^{63}Q_x[k]Q_w[k],\qquad t=\operatorname{sat}_{48}(a+Q_b).$$

偏置相加使用 49 位临时结果；超范围时截到 signed48 端点并置 overflow。输出为 $Q_y=\operatorname{sat}_{32}(\operatorname{RNE}(t/2^r))$，对应实数为 $Q_y s_xs_w2^r$。移位 r 从保守整数范围直接推导，全层固定。改变 r 而不改变解码系数会破坏实数意义。

RNE 在恰好半值时取偶数。例如右移 1 位：3→2、5→2、−3→−2、−5→−2；它与直接算术右移不同。先饱和 raw48，再 RNE，最后饱和 int32，顺序不能交换。

## 2. 手算一个 DOT64

取 X 前三项为 1、−2、3，W 前三项为 2、4、−1，其余 61 项为 0，bias=1，shift=0。三个非零乘积为 2、−8、−3，点积为 −9，加偏置得到 −8；raw48 与 int32 都应为 −8，两个范围标记均为 0。

硬件只在 `in_valid && in_ready` 的上升沿接受乘法操作数。输入停顿不能增加计数；恰好第 64 次接受后才完成。最后一个乘积通过寄存器更新进入累加器，随后 FINALIZE 使用更新后的累加器，因此不会漏掉末项。输出有效后必须保持数据和标记，直到消费者接受。

可检查动作：运行 `bash scripts/run_dot64.sh`，打开 `reports/prototype/dot64/dot64.vcd`。自动波形检查应数到 64 对输入并还原首笔 −8；只看 busy 翻转不足以验证乘加。

## 3. 同步存储为什么多一拍

RAM 在上升沿采样地址，用非阻塞赋值更新读数据。同一个上升沿的 MAC 看到的是之前的读数据，不能把刚提交的地址当作立即可用的操作数。

控制器先在 B_REQ 读取偏置，再在 DOT_START 提交点积任务。PRIME 提交 k=0 的 X/W 地址；进入 FEED 后，MAC 每拍消费当前数据，同时 RAM 预取下一项。k=63 时不再预取，等待 DOT64 返回结果。wrapper 没有组合数组读取，也没有逐字复位；复位清的是控制和有效标记，旧 RAM 内容不会自动成为新任务。

W 的数学形状仍是 [64,256]。存储顺序改为 `W_pack[n][k]=W[k,n]`，使一个输出列的 64 个权重连续。改变的是地址顺序，不是转置后的另一个算子。

## 4. 从点积变成完整矩阵

外层 m 遍历 99 行，中层 n 遍历 256 列，内层 k 做 64 次乘加。当前行第 256 个输出真正写入行缓冲后才出现 ROW_READY。等待期间 BUSY 保持为 1，行号保持；可以重复读取，ACK 必须携带当前行号。

ACK 消费一行后才覆盖缓冲区。最后一行 ACK 后才 DONE；算完末行但尚未 ACK 不能宣布任务结束。十二层是十二组独立 X/W/b，不把上一层 FFN1 输出直接喂给下一层。连续装载新任务验证参数切换和旧状态清除。

资源形态是 X 6336×16、W 16384×16、b 256×48，加一个 256×34 行缓冲（32 位结果及 2 个标记）。没有完整 99×256 输出 RAM。行为 RAM 尚不等于真实 SRAM 宏映射，仿真周期也不能证明 150 MHz。

## 5. 自测与答案

1. shift=1 时 −5 为什么得到 −2？答案：−2.5 恰好半值，邻近偶整数是 −2；向负无穷取整会错误得到 −3。
2. 最后一行出现 ROW_READY 能否立刻切换权重？答案：不能。BUSY 仍为 1，装载会被拒绝；最后 ACK 后再 load_begin 并重新完整装载。
3. 第 64 次输入处出现停顿，能否开始加偏置？答案：不能。计数依据已接受的握手次数，必须先接受满 64 对。
4. 为什么 36 案例有 912384 个结果？答案：每例 99×256=25344，乘以 36；实际有效 MAC 次数为 912384×64=58392576。
5. 复位后 RAM 不清零，会不会读到旧结果？答案：公开有效状态已清除，START 要求重新完整装载，读回要求 ROW_READY。只读取数据引脚而忽略 valid 不符合接口。
