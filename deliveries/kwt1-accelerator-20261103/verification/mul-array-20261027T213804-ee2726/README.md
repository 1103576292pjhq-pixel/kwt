## 数据从哪里来

没有下载数据，没有使用音频、模型权重或DEV12作为本次乘法组件的输入。数据由本工程新增脚本 `scripts/verify_mul_array.py` 生成，保存为本目录 `vectors.txt`，每行对应一个测试拍。

1. 手算数据：X=[1,2,3,4]，W=[5,-6,7,-8]，预先写出16个字面乘积，检查行列位置与负号；另检查全零。
2. 极值：signed16乘积上界(-32768)×(-32768)=1073741824，下界(-32768)×32767=-1073709056。
3. 边界集合：[-32768,-32767,-4096,-1,0,1,96,4096,32766,32767]。用100组输入让每个lane都遇到全部10×10对组合。
4. 标签压力：4种ctx×16种mask×2种last，共128组，检查标签原样随乘积寄存。任意last仅是组件透传压力，不代表外围调度合法性。
5. 连续两块：512组连续输入，按k0/g0到k63/g3排列；每个k的X供四个g复用。第一块只有k63非零，第二块为固定种子随机数据、mask=0111。
6. 随机压力：Python `random.Random(20261027)` 生成4,096拍，输入整数范围为[-32768,32767]，混合有效拍、空拍和复位。其他随机序列也由同一实例生成，所以完整向量以保存文件和SHA256为准。
7. 无效拍/复位拍送入未知值X，检查其不污染已知乘积；最终有效拍后送入两个空拍，检查末组输出及valid清除。

Python使用任意精度有符号整数直接计算 `X[p]*W[q]`，再转成32位补码位图供TB比较。它不读取RTL内部结果，也不提前右移或饱和。

与已有黄金的连接是交接文档的k63锚点：仅最后项X=-4096、W=96，bias=0，调用原有 `dot64_scalar` 得到raw=-393216、Y=-6、flags=0。该检查用于确认测试数据的尺度解释；RTL此次只比较原始32位乘积，并未实现或验证点积累加和量化。

## 每拍怎样检查

在时钟下降沿驱动输入，1ns后确认寄存输出尚未变化，验证组合输入变化和拉低同步复位不会立即改变输出。在上升沿后1ns检查乘积和标签，避开非阻塞赋值的调度竞争。

检查输出valid、ctx、mask、block_last，并逐lane比较16个乘积，使用四态不等比较以检出意外X。首次有效输入之前乘积寄存器允许未知，因为其规格不要求复位payload。首次有效输入后，空拍与复位期间的数据保持也检查。

本模块只透传mask，不屏蔽乘法结果；无效行禁止更新acc的行为属于下一模块。无ready接口，本次不执行背压测试。

TB还核对所有公共宏与冻结规格一致，并重复include头文件检查保护宏。flags宏的位号检查不代表flags生成RTL已实现。

## 证明测试能检出错误

仅在本验证目录生成错误副本，没有改写生产RTL。

| 故意注入的问题 | 被检出的位置 |
|---|---|
| 乘法按无符号解释 | 第4拍lane1，得到65530，期望-6 |
| W列顺序反转 | 第4拍lane0，得到-8，期望5 |
| 丢弃block_last | 第6拍标签不符 |
| 空拍仍输出valid=1 | 第2拍valid不符 |
| 复位后valid仍为1 | 第1拍valid不符 |

这些错误副本的仿真退出码1是预期结果，五个副本的编译退出码均为0，避免把语法错误误当成功检错。它们不构成形式证明或完整故障覆盖率。

## 延迟、吞吐和验证边界

当前接口为一级乘积寄存：上升沿采样有效输入，该沿后乘积和标签更新，下游可在下一上升沿消费。连续输入测试确认每拍可接收一组、每组16个乘积。声明寄存状态为512位乘积与8位有效/标签，共520位，不能据此推导物理面积。

尚未验证四上下文acc、bias/量化RTL、真实SRAM返回、流水排空连接、完整矩阵Y/flags、系统背压或PPA。连续两块测试验证的是乘积和标签流，没有acc可供检查，因此不宣称累加上下文隔离已通过。TB的10ns周期只是仿真激励，不是达到100MHz或150MHz的证据。
