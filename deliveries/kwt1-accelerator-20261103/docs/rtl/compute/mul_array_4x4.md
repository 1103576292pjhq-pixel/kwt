# mul_array_4x4：16路乘法阵列开发记录

整理：2026-10-29；来源：本对话、当前源码和既有验证。源码：[mul_array_4x4.v](../../../rtl/compute/mul_array_4x4.v)。公共位宽来自 [kwt_compute_config.vh](../../../rtl/include/kwt_compute_config.vh)。

## 背景与用户思路

计算核每次收到同一k下四行X和四列W，形成4×4外积。用户最初提出：接收SRAM读出的4行W/4列X、握手和最后一组标签，输出16个乘积；考虑用数组和for计算。之后讨论并确认本接口实际为四行X、四列W。

需要补充的地方：操作数应是已对齐的返回数据，不是SRAM当前请求；四个X和四个W分别装进64位总线，一次握手仍是一组数据；硬件中的固定循环可展开并行计算，不自动逐次消耗16拍。

## 最终职责与接口

| 接口组 | 位宽及含义 |
|---|---|
| clk/rst_n | 上升沿、低有效同步复位 |
| in_valid | 本拍操作数与标签有效；本模块没有ready |
| in_x/in_w | 各64位，4个signed16位图，元素0放最低16位 |
| in_ctx/in_row_mask/in_block_last | 2/4/1位，分别为上下文、行有效信息、本块最后一组 |
| out_valid/out_product | 有效位和512位乘积总线，16个signed32 |
| out_ctx/out_row_mask/out_block_last | 与乘积同沿寄存的标签 |

X为Q12，W为Q16，乘积保持完整Q28，不做右移、舍入或饱和。lane=p*4+q，乘积放在out_product[32*lane +: 32]。

## RTL组织与时序

```verilog
assign x_lane = in_x[16*p +: 16];
assign w_lane = in_w[16*q +: 16];
assign product_comb = x_lane * w_lane;
```

片段用于解释固定尺寸，生产代码使用宏。x_lane、w_lane和product_comb明确声明signed。两层generate生成16条组合乘法及各自的32位寄存切片。

| 上升沿 | 本模块动作 | 下游累加 |
|---|---|---|
| A | 接收有效X/W，沿后更新乘积、valid和标签 | 仍采样前一组乘积 |
| B | 可接收下一组 | 接收A沿寄存的乘积 |

没有ready意味着下游必须接收每组有效输出；不能直接接一个会任意停住的消费者。顶层通过有限块输入及累加可持续接收保证这一点。

## 讨论与优化记录

| 用户问题/建议 | 最终处理及原因 |
|---|---|
| 用数组和for算16个乘积 | 接口使用打包总线；内部generate展开16路，数组不是必须条件 |
| 为什么64位输入仍是一组 | 64位携带4个16位元素，分组是一次传输的含义，不等于元素数量 |
| 用.v、公共宏、中文注释 | 已采用；注释显示方框需区分编码与字体，不能通过改算法解决 |
| 不支持背压会不会出问题 | 模块有持续接收前提，外围不能在有有效乘积时拒收；顶层按该合同连接 |

## 注意点

- p、q是展开时常量，不是时钟计数器；16路在同一沿寄存。
- 标签必须跟实际操作数同拍延迟，不能使用另一拍的请求编号。
- 输入空拍令out_valid变0；乘积和标签保持不代表可重复消费。
- 复位清有效和标签，不要求清512位乘积寄存器；无效数据不得使用。
