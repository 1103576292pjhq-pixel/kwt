# result_convert：偏置与量化开发记录

整理：2026-10-29。源码：[result_convert.v](../../../rtl/compute/result_convert.v)。

## 背景与用户思路

用户提出：输入计算结果和bias，相加后右移16统一尺度，进行RNE舍入、溢出处理，输出最终结果和标签。

讨论纠正：输入是完整K64累加后的acc40，不是单个乘积；acc和bias都是Q28，不用先对齐移位；舍入需要保留低16位余数，不能先丢弃再处理；加bias的raw40溢出与最终Y16饱和是两个不同阶段。

## 冻结运算链

```text
acc40/Q28 + bias32/Q28
          ↓ 符号扩展相加
       临时和41位
          ↓ sat40
        raw40
          ↓ RNE除以65536
       舍入结果
          ↓ sat16
        Y16/Q12
```

右移16来自28−12，不是可配置shift。加bias后检测41位和的最高两位是否不同；超范围先钳位signed40，再舍入和sat16。

## 接口与背压

| 接口 | 含义 |
|---|---|
| in_valid/in_ready | 接收acc、bias、global_last的握手 |
| in_acc/in_bias | signed40/signed32 |
| in_global_last | 本项是否整个矩阵任务的最后输出 |
| out_valid/out_ready | 最终Y及flags的交付握手 |
| out_y/out_flags | signed16，3位flags |

输出只有一个寄存槽：

```verilog
assign in_ready = rst_n && (!out_valid || out_ready);
```

没有旧输出，或旧输出本拍能被消费时，可以接收新输入；可同沿消费旧输出并接收新输入。输出受阻时valid/Y/flags保持；复位取消尚未消费的输出。

## RNE的关键实现原因

- 使用绝对值的商和余数：余数大于半单位进位；恰好半单位且商为奇数才进位。
- magnitude是unsigned40，因为abs(−2^39)=2^39放不进signed40正数范围。
- 右移后的商24位，舍入幅值补到25位；恢复符号和比较边界均保持signed25，不能让符号位误解释正数。
- 先完成舍入再sat16，正端32767.5舍入到32768后应钳位32767并设置饱和标志。

手算锚点：+2.5→2、+3.5→4、−2.5→−2、−3.5→−4。

## 讨论与优化记录

用户要求把易混淆点直接写入对应RTL注释，随后自行阅读优化，并要求助手接收磁盘版本再验证。验证接收期间没有用旧版覆盖用户实现。

原“输入乘积”的说法更正为“输入acc”；原“先右移再舍入”的描述更正为“保留余数参与RNE”。保留raw溢出、Y饱和、global_last三种flags语义。

顶层仍逐项QISSUE/QWAIT服务，没有因为本组件支持同沿收发就未经讨论改成多个量化器或重叠块计算。
