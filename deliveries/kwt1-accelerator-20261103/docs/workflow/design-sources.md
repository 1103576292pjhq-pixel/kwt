# 当前设计依据：仅以赛方资料为外部规范

生效：2026-10-31。用户明确要求：“现在不要看交接包的东西了，不要让他影响你，现在唯一指导你的就是赛方的资料。”

随后用户进一步澄清：“交接包中有用的就是架构而已……其他的按照你自己的想法。”因此保留用户已确认的整体架构与数值方案；具体接口、协议、位宽及控制实现独立按当前需求设计，不为旧包兼容保留遗留字段。不能把此规则解释为推翻已确认架构。

## 执行规则

1. 只保留用户已确认的架构层选择；不再查阅或仿照交接包的具体实现，也不以兼容该包、其驱动或ABI为新增设计理由。
2. 外部规范仅取自赛题指南、赛方补充说明、用户指定为赛事框架的E203仓库，以及赛方SRAM模型/手册。公开E203源码事实不自动等于服务器修改版或完整赛事平台事实。
3. 每项结论区分“赛方明确要求”“指定框架源码事实”“需要自行设计的工程选择”。缺少规定的参数不得借交接包补齐，须按本工程功能需求分析并与用户讨论。
4. 此前的命令FIFO深度8、PAIR/PAIR_NEXT、legacy/fast兼容、48位命令载荷、固定寄存器表和ACK格式，不能继续作为已确认接口规范。若某机制有独立功能需要，重新说明原因、代价和接口后决定，不默认保留，也不无分析删除。
5. 已完成RTL保留，不擅自重写或覆盖用户修改；现有源码是待核对的实现，不是规范来源。接口中带入的历史约定需另行审查，功能TB通过只证明其测试合同，不能证明赛方要求如此。
6. 共享RAM模型及地址等自行假设标记为临时开发约定，不能称为赛方提供或规定。SRAM宏级仿真、平台联调和赛事验收仍独立记录。
7. 沿用用户协作流程：先解释/讨论接口与逻辑，再按授权写RTL、阅读优化、按要求验证；公共位宽引用宏，中文注释。

## 已指出的具体问题：48位装载载荷

当前ICB写数据32位，X/W有效16位，bias有效32位。48位装载容器只有旧接口兼容来源，没有当前功能必要性。用户随后已授权修改，当前装载口已改32位，X/W检查高16位符号扩展，bias直接signed32；同时删除运行时shift，收窄身份索引及结果序号，并独立设计ICB寄存器与一项命令缓冲。计算核和SRAM有效数据位宽不变。新协议见[ICB说明](../rtl/accelerator/icb-interface.md)，不再默认深度8或PAIR协议。
