# KWT1 本科加速器：个人架构规格修订稿

日期：2026-10-27。规格身份：`KWT1-FFN1`。

本轮用户已明确：先改架构规格并逐项讲清，RTL之后再写。本文是供用户理解及后续实现的个人规格，不表示团队已采纳，也不表示新RTL已经实现或验证。原交接包、个人独立核及既有测试/性能记录均未改写。

阅读顺序：[本规格](README.md) → [完整原理讲解](module-guide.md) → [设计选择与常量依据](decisions.md)。历史源码阅读结论另见[原包架构阅读记录](../source-review.md)，不能用本文覆盖“原包实际仍是48位”的历史事实。

平台来源补充：[E203仓库与共享SRAM资料清单](platform-sources.md)。

## 1. 已确定的方向与本轮取舍

沿用用户确认的X16/W16/product32/bias32/acc40/out16、Q12/Q16/Q28/Q12、固定RNE右移16和sat16。保留新包的16MAC、四上下文、全X四bank、双W槽、命令FIFO8、PAIR_NEXT、双结果块及ICB系统边界。

只改算术位宽会留下可变shift、bias范围未校验等规格漏洞；整包重新设计则会引入没有数据支撑的结构变化。本稿采用“保留已解释的功能结构，收紧数值与控制约束”的方式。这里的新细节是本轮提出的个人规格，后续实现前应以用户实际审阅的版本为准。

不因暂时不理解就删除机制：先解释用途、识别其必要前提；无需求支持的功能从正式合同移出；有功能依据但没有最佳参数证据的内容明确标注为待测参数，不伪装成最优。

## 2. 任务边界

正式配置固定M=99、K=64、N=256。计算Y=XW+b，每个Y独立含64个乘积，单任务25,344项Y及同数flags。共十二套独立层参数任务，不是片上自动运行完整十二层网络。

不接收原始音频、浮点NPY或模型文件；浮点到定点的量化在外部完成。本科B与研究生G是并列模式端点，G不是B的自动后级。本文只规定B的定点算术与系统边界，不修改G的FP32数值合同。

其他矩阵尺寸需匹配的重新实例化、描述符和验证；软件函数允许某个m/n取值，不构成固定99×256硬件支持运行时变尺寸的证据。本规格不承诺任意小几何。

## 3. 必须统一的数值合同

| 对象 | 有效位宽/小数位 | 含义 |
|---|---|---|
| X | signed16 / 12 | 实数=编码整数×2^-12 |
| W | signed16 / 16 | 实数=编码整数×2^-16 |
| product | signed32 / 28 | 精确16×16乘积 |
| bias | signed32 / 28 | 与乘积尺度一致，直接相加 |
| acc | signed40 / 28 | 按k0..63顺序累加 |
| 加偏置临时和 | signed41 / 28 | acc与bias先各自符号扩展，再相加 |
| raw | signed40 / 28 | 临时和经过sat40后的值，组合内部量 |
| Y | signed16 / 12 | RNE(raw/2^16)，再sat16 |
| flags | 3个有效位 | bit0=raw溢出；bit1=输出饱和；bit2=全局最后项 |

正式入口的shift必须等于16，其他值非法。硬件正式路径采用常量右移/截位与RNE，不提供0..47的可变量化功能；组件若另设可变shift试验，必须使用不同配置身份，不能扩大正式任务合法域。

每个前缀的数学规则沿用sat40。合法K64输入的所有前缀都不可能溢出，因此允许通过范围证明实现普通40位加法；无需为了不可达溢出额外插入每拍饱和器。最终41位加偏置、sat40及overflow定义须明确，便于组件边界验证。

RNE：取绝对值，商=mag>>16，余数=mag低16位；余数大于32768时进位，等于32768且商为奇数时进位，随后恢复符号，再限幅到[-32768,32767]。负数tie也必须取偶数。

### 3.1 40位为什么足够，为什么采用40而非48

signed16乘积范围为[-1,073,709,056，1,073,741,824]。64项和的范围为[-68,717,379,584，68,719,476,736]；加任意signed32 bias后为：

`[-70,864,863,232，70,866,960,383]`。

signed40范围为[-549,755,813,888，549,755,813,887]，覆盖所有结果及前缀。signed38理论上也足够；40位是用户已选定、已有个人RTL与数值依据的规格，保留余量并减少重新更改共享合同的成本，并非算法强制的最小位宽。

四上下文、W双槽、FIFO和结果块不会把不同输出相加，不构成扩大到48位的理由。量化精度由尺度、舍入和饱和决定；合法任务中48→40不产生额外误差。

### 3.2 容器与合法性检查

- 外部legacy命令数据仍可保留48位，原因是既有命令ABI兼容和保留完整原始值以检查非法输入；这不是48位算术要求。
- X/W仅接受48位载荷恰好等于低16位的符号扩展。
- bias仅接受48位载荷恰好等于低32位的符号扩展；通过检查后只存32位。不能先截断再判断。
- 共享bias仍用int64容器，调用端必须提供合法signed32值；不能依赖取低48位代替int64范围检查。
- 共享Y和MMIO响应使用32位容器；sat16结果在边界符号扩展，内部结果寄存及payload仅存16位数值。
- 未使用的48位registered out_raw调试端口不纳入新生产量化器合同；内部raw40及overflow计算保留，调试可由验证观察，不额外保存无消费者的raw结果。

## 4. 相对交接包的明确规格变更

| 编号 | 原包实际行为 | 本人规格要求 | 修改原因 |
|---|---|---|---|
| C01 | acc48 | acc40 | 与已确认数值规格统一，合法K64范围已证明 |
| C02 | bias存储/选读48 | bias存储/选读32 | 正式bias仅signed32，扩展在加法边界进行 |
| C03 | 加偏置49位、sat48 | 加偏置41位、sat40 | 配合acc40，保留显式溢出语义 |
| C04 | 量化内部输出32，填块时取16 | 内部输出16，外边界扩展32 | 饱和目标本来就是signed16 |
| C05 | BEGIN接受shift0..47 | 正式BEGIN只接受16 | 固定Q28→Q12，无运行时变尺度需求 |
| C06 | bias命令无signed32范围检查 | 检查48位是否为signed32正确符号扩展 | 防止非法高位被静默截断 |
| C07 | 部分内部索引用integer | 按第7节范围定义专用位宽 | 区分内部计数需求与CPU32位容器 |
| C08 | 可变shift、任意bias48组件向量 | 使用正式shift16/bias32向量；异常输入单独验证拒绝 | 原组件全域不等于新正式合法域 |
| C09 | 通用历史sat32参考与正式sat16工具共存 | 只使用与本规格绑定的sat16参考作为生产黄金 | 防止验证入口相互矛盾 |

命令FIFO中的48位原始载荷、任务ID32、MMIO数据32和共享bias64保留时均有接口原因，不属于需要盲目全部改成40位的对象。

## 5. 计算与存储结构

PM=4、PN=4、CTX=4，总16路乘法器。一个块为四行×十六列，四上下文各保存4×4个输出。对每个k按g0/g1/g2/g3轮转，共K×CTX=256次请求。X只在g0读取、返回后保存于x_hold，供后续三个g复用。

X四bank，各深度ceil(99/4)×64=1600，每字16位。bank=r%4，addr=floor(r/4)×64+k。W两槽，各四bank，深度CTX×K=256，每字16位。tile内bank=c%4，addr=floor(c/4)×64+k。W输入顺序index=k×16+c，区别于共享内存中的列主序W[col×64+k]。

每槽16个bias32，与其W共同拥有。活动槽读、装载槽写，禁止同物理SP bank同拍读写。W槽在该tile最后行组成功publish后释放，不提前至最后MAC，不推迟到CPU ACK；publish切断当前tile的全部W/bias依赖。

X逻辑12,800 B，W逻辑4096 B，bias128 B，acc320 B。结果payload保持2×64×19=2432 bit，即304 B。以上不是物理SRAM容量或面积。

正式存储宏尚未选择。按指南允许的16×128/1024/4096形状、真实端口/时序/面积再拼接；bank数量不等于宏数量。不能以服务器存在其他深度就视为准入。结果块组合peek/寄存响应与X/W同步读不同，不能统一套一个未适配的SRAM封装。

## 6. 时序与控制责任

生产SoC基线读延迟L1。读请求有效位与k/g/mask/task/row/tile/slot一起延迟。返回形成product32，下一流水阶段更新acc40。每个g每四拍复访一次；这提供交错调度条件，不构成150MHz时序保证。

状态职责：LOAD收数据；CLEAR清当前64个acc；RUN发256次请求；FLUSH等k63/g3乘积真正累加；ALLOC等空结果槽；QISSUE/QWAIT用单份量化器逐项填块；PUBLISH完整发布；WAIT_TILE等下一槽READY。

保留单份量化器及当前先算后量化调度。双结果块只解耦CPU消费与核心生产，不声称已实现计算下一块与量化当前块重叠。不擅自增加第二套acc或第二量化器。

## 8. 输入与输出协议

输入保留BEGIN/X/OPEN/W/bias/COMMIT/START。X全量装载后OPEN tile0，装W1024+bias16后COMMIT，随后START；只提交首tile再START，避免第二次OPEN在两个槽占用时挡住START。启动后装载后续tile，与计算和结果服务重叠。

命令FIFO八项保留作当前兼容配置，不称其最优。一个pair占一项，先低半再高半；第二半被核心接受后才释放。PAIR_NEXT只对X/W有效，偶索引且合法范围，成功入队才位置+2，失败保持；不向tile进位。

MMIO写成功只代表入队；核心q退休后才执行命令并判断语义错误。非法bias在该阶段报错且不写bias，不以裁剪到合法范围替代拒绝。错误保持到明确恢复，不靠读状态清除。

两个结果槽FREE→FILL→READY→FREE。alloc绑定row/tile/count/task/final；量化填入index=row×16+g×4+col，written_mask防重复/越界；完整后publish并赋sequence。CPU根据描述符和cursor重建index=(row+cursor/16)×256+tile×16+cursor%16。

读RESULT只在本地成功响应退休时推进cursor，命令接受时先快照响应。整机中B的响应先被guard接收并保存，guard再等CPU接收；这是两级响应边界，不能把所有rsp_ready当成同一条线。guard在上游响应未退休前不接下一条请求，从而防止重复访问和过早切换。

匹配ACK在命令接受沿释放结果owner；ACK响应仍须排空。ACK必须task/sequence/count匹配且整块读完。CPU先写共享Y/flags、fence，再ACK。结果存满时核心在ALLOC等待；输入等待循环必须同时服务结果，避免循环等待。

legacy与fast共用同一结果队列，不另建Y副本。fast RESULT把y16+三标志装进32位；每块共享描述符。旧接口保留是当前ABI兼容选择；若以后移除，需单独修改固件/能力标识和验证，本轮不隐式移除。

## 9. 系统完成、模式与恢复

最后MAC→最后publish/compute_done→B task_done→guard COMPLETE是四个不同边界。

B task_done还需输入FIFO/q空、结果消费/ACK结束、核心及本地响应安静。guard COMPLETE再要求B/G均无未完成工作、共享mem无pending/当前accept、任务session有效且epoch/task token匹配。CPU观察到core_done不能直接把共享Y当作完整结果。

host/CPU共享RAM一次一笔事务，owner从命令接受保持到响应退休；无同拍响应退休再接新事务的吞吐承诺。MMIO要求4字节对齐及完整写mask，RAM支持byte-enable但不由此推导CPU可任意非对齐访问。

ABORT允许取消未完成算术；已接受的响应必须先排空，不能flush吞响应。复位/flush清状态、valid和owner，不逐项清X/W/结果payload/共享RAM。所有待读数据必须已被本任务合法装载。

## 10. 预计变化与不能继承的结论

新包acc64×48→64×40减少512个声明状态位；bias32×48→32×32减少512位，合计1024 bit，即128 B逻辑状态。量化输出若由32位寄存改16位，另少16位。结果payload、X/W bank和16个乘法器不变。

固定shift16可避免正式路径承担可变移位的功能，但综合工具实际去除了多少逻辑、面积/时序/功耗变化，要后续测量，本文不填写预测百分比。去除原未使用raw寄存端口也不能当作确定面积收益：原综合可能已把它消掉。

本稿不增加流水级，目标保持原调度与接口握手；真实周期等价需要新RTL与原包在同输入/背压下比较后确认。原包F3的29,068,416拍是历史整机记录，个人旧核的通用综合减少6.15%也属于另一份实现，均不能作为本规格未来RTL的新实测结果。

## 11. 后续实现必须验证的事实（本轮未运行）

1. 合法signed16/K64/bias32的全部Y与flags符合个人冻结数值模型及绑定fixture；拒绝非法bias高位与shift非16。
2. 正负RNE tie、输出正负边界、仅k63非零、有符号乘法与尾行mask。
3. W双槽装载与计算重叠，无提前覆盖；最后tile行组publish才释放。
4. 非线性fill覆盖、两结果槽满背压、RESULT响应保持、错误ACK不释放、最后ACK尾响应。
5. PAIR低高半、满FIFO、PAIR_NEXT失败不前进、同拍入出计数及完成哨兵不回绕。
6. guard两级响应、共享owner、模式token、ABORT排空与连续任务旧结果隔离。
7. 指定宏读延迟/掩码/保持/碰撞合同，随后进行同配置综合与STA/PPA。

这些是未来验收条件，不是本轮新增PASS。新规格仅承诺合法任务数值一致；任意旧bias48或shift47压力向量不在新合法域内，不能要求与旧容器全域等价。

## 12. 仍待证据解决的事项

- SRAM具体型号、拼接数量、结果块实现形式及真实延迟：缺正式宏合同与PPA，保留逻辑需求，不虚构宏数。
- FIFO深度8、16MAC资源点、单份量化器是否最优：均有功能理由，最优性尚未证明；需要同条件测量，不随机更改数字。
- 正式150MHz、面积≤2.25mm²、全系统能耗：不能从逻辑bit数或仿真时钟推导。
- F3统一生产固件的正常G12/BGB/连续B12和官方精度/性能资格：不能继承不同固件历史PASS。

上述待证据项不影响把已确认的数值与接口原因写清；后续每个选择应记录依据和代价，用户可逐项追问，不再以“旧版本就是这样”作为充分解释。
