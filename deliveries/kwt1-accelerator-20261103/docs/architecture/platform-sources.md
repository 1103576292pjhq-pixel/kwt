## 2. 共享SRAM要分清的三个层面

| 层面 | 已知资料 | 仍须核实的内容与来源 |
|---|---|---|
| 算法/系统使用 | 架构中CPU从共享RAM读X/W/bias并写Y/flags；共享容量要求512KiB | 官方是否预集成该模块、哪些地址区可用、host/CPU装载方式；看正式顶层、平台说明、TB/SDK |
| 总线与控制器 | 原包icb_shared_ram模型设基址0xa0000000、131072×32、4字节写使能、同步读、一笔在途 | 官方实际ICB接口、地址译码、读写延迟、背压、响应保持、错误行为、仲裁和复位；不能将原包模型默认当官方实现 |
| 物理SRAM宏 | 原包仍用行为数组；公共E203代码不等于指定工艺存储库 | 赛方服务器或官方资料中的Verilog模型、端口手册、时序说明和后端库；具体型号、允许形状、拼接数量、掩码与碰撞语义 |

如果正式平台已经提供共享512KiB模块，B端通过CPU/总线使用其接口；不能再把512KiB放进本科加速器内部作为一份“免费”存储。若平台要求自行实例化共享存储，则由正式集成合同决定实现者和映射方式，当前不能猜。

本科内部X四bank、W双槽是另一组局部存储。其端口、并行带宽和面积归属单列；同样需要与赛方准入宏适配，但不是共享RAM的替代品。ITCM/DTCM也另列。

## 3. 从服务器优先读取什么

对用户的RTL工作，先读取或记录以下项目即可，无需先复制整套工艺库：

1. 官方SoC顶层、存储控制器/wrapper、地址译码和加载TB：确认共享RAM是否已经提供、接在哪条通道、容量/地址/接口是什么。
2. 共享RAM和候选内部SRAM的Verilog模型或端口声明：确认时钟、CS/WE极性、数据/地址宽度、SP/双端口、byte/bit写掩码。
3. 手册/时序说明：确认读延迟、无读使能时输出保持、读写冲突、复位和初始化行为。
4. 宏文件清单及版本：让RTL行为模型、综合库和后端宏采用同一身份。候选形状须符合指南许可，不能只因目录存在就采用。

正式面积/STA/功耗还需.lib或.db等时序库；物理实现通常还需LEF及相应版图视图，具体由赛方后端流程和队友分工决定。写RTL时最先需要的是接口和行为合同，不是先拿齐所有物理视图。

## 5. 资料未齐时的暂行开发基线

当前建议沿用交接包的共享RAM模型推进本科架构理解及后续功能开发；它是个人开发假设，不能改称赛方正式实现。此前用户已明确RTL之后再写，本次仅补充规格，不启动RTL修改。

| 项目 | 暂行基线 | 状态及适配边界 |
|---|---|---|
| 共享容量 | 512 KiB | 沿用赛题容量条件；平台预集成情况、保留区和具体可用布局仍待确认 |
| CPU侧接口 | 32位ICB、4字节写使能、一次全局在途 | 与现有集成模型一致；由valid/ready处理等待和响应保持，不把整个访问假定为固定一拍 |
| 共享基址 | 0xa0000000 | 交接包暂定值，集中定义并与软件/加载数据保持一致；不是已确认的官方地址 |
| 本地行为模型 | 同步读，响应寄存，复位不清数据 | 用于功能仿真；不能代替物理宏或生成最终面积/功耗结论 |
| 真实宏型号及数量 | 暂不指定 | 有正式端口/时序/库身份后再适配，不能随机猜型号 |
| 本科内部X/W | 保持独立bank与已定义固定读延迟合同 | 不与共享RAM混用；真实宏延迟改变时必须同步适配tag与返回数据 |

本科乘加核心只看到内部X/W bank和结果接口，不应依赖共享基址、共享宏型号或CPU每次访问用几拍。共享RAM由CPU/SoC集成侧连接；共享容量不作为B内部新增的一份512KiB存储。

拿到正式平台资料后，对照更新共享控制器/wrapper、地址译码、软件常量和匹配fixture。接口或延迟变化可能需要相应控制适配和系统回归；不假定只换一个参数就全部兼容。若变化仅在共享RAM实现且保持其总线合同，矩阵乘加的数值规则和分块结构无需因此重设计。
