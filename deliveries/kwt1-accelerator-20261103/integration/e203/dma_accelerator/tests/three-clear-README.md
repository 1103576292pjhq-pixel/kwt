# 三任务清空与重新加载回归

入口：`run_three_clear.py`，在安装了 Icarus Verilog 的 WSL 中运行。

同一仿真实例按顺序执行既有验证数据 case1、case2、case3，对应模型第1、2、3层。
脚本检查既有12任务数据清单的哈希，并转为共享SRAM所用的行优先W排列。
三次任务均重新加载全部X、W、bias，校验400块、25344输出和边界保护字。
输出由实际共享总线回读获得，再逐位对比整数黄金，并分别计算浮点参考NRMSE。

每次任务开始前：

- 拉低公共复位4拍，复位后检查DMA状态、内部装载计数、任务有效标志、权重槽和结果槽为空闲。
- 通过正常共享ICB接口将X、W、bias、Y的48320个32位容器清零，并全部回读确认零值。
- 清空检查结束后才开启该任务的输入装载计时；清空开销单独打印。
- 内部SRAM物理位不逐地址清零，采用有效状态失效及完整重新装载。该事实在报告中明确标注，不能描述为内部SRAM已写零。

反向测试 `--skip-reset` 保留第一个任务结束状态，必须在第二次任务的状态清空检查处失败。

这是本地CPU总线BFM和SRAM功能合同模型下的RTL回归，不是实际E203指令执行或服务器官方SRAM模型测试。
不得将其周期替换服务器DMA06的单任务周期，也不得将3任务结果标成指南正式12任务吞吐。
生产RTL不修改，旧版单任务服务器包不覆盖。
