# DMA版12任务服务器预评测

唯一服务器入口：`run_suite.py`。默认12任务，并导出每个任务的活动信息。
使用现有验证划分中覆盖模型12层的12个样本，非组委会提交冻结后抽取的正式评测任务。
任务定义是99×64乘64×256加偏置，输出25344项，每项报告整数逐位一致性及浮点NRMSE。

## 执行与计时

编译一次，顺序执行12次独立的仿真进程，采用相同可执行文件、同一份固件与同一配置。
每次平台从复位状态启动，任务间的进程启动、复位、校验时间不加入有效时间。
这不是无复位连续运行测试；同一实例的三任务清空回归另有本地记录。

任务前经ICB逐地址清零X/W/bias/Y共48320个32位容器，并全部回读检查。
不清零整块512KB，也不直接修改宏模型内部数组。
内部缓存采用复位使有效标志、装载计数和槽位失效；内部SRAM物理存储位不逐地址写零。
在CPU第一次共享访存时检查缓存为空，固件在配置DMA前检查DMA状态为零。
只在清空完成、浮点/整数参考已装入且层号元数据已发布之后开始有效装载。

每个有效窗口：第一次X写请求提出 → 最后一项Y写响应退休。
窗口包含X/W/bias装载、CPU启动和输出预填充、DMA配置、轮询、总线等待、计算和写回。
软件黄金回读校验在最后写回之后执行，不加入吞吐窗口，但必须通过才能计作完成任务。
吞吐=任务数×频率/各任务窗口周期之和；不取各任务吞吐的算术平均。
150MHz仅目标归一化，必须另做STA。仿真实际时间和实际仿真时钟下吞吐也单列。

## 指标与文件

- `report.json`：状态、所有任务结果、总周期、平均延迟、吞吐、数据与源码身份。
- `metrics.csv`：每任务周期、装载周期、精度和CPU/DMA共享总线读写次数。
- `case01/`至`case12/`：该任务日志、实际结果回读、报告、`activity.vcd.gz`。
- `compile.log`、`soc.f`、`shared.f`、生成的生产与仿真顶层：复现入口。

访存计数覆盖有效窗口，区分加载器写、CPU共享读写、DMA读写，记录有效传输字节。
CPU/DMA命令等待、共享侧命令等待、待响应周期及配置事务数也保存。
这些等待量可能重叠，不应相加作为互斥耗时分解。
共享总线访问数不等于内部物理SRAM宏访问数，后者尚未统计。

活动导出范围为SoC实例，包含E203、加速器、互连、共享存储实例。
VCD从测量使能时开启，最后写响应后1ps关闭；精确窗口以TIMING_WINDOW为准，功耗分析时需裁剪。
RTL活动仍需映射至综合网表、检查覆盖率，并使用SRAM功耗模型；不能直接当作功耗结果。
VCD逐任务压缩；可用`--activity none`禁用，但该次运行将不具备这套活动素材。

## 服务器使用

在kwt-soc中新建目录解压，不覆盖accelerator/rtl或原顶层。

```bash
python3 dma_suite_test_01/kwt-dma-suite/run_suite.py --root /storage1/2026contest/server2/s2_21usr/Desktop/e203-integration/kwt-soc --output verification/dma_suite12_01
```

每项显示TASK_START、TASK_PASS；全部通过后才显示PASS_E203_DMA_SUITE_12。
任何错误会停止并保留已完成结果。不要把部分通过称为12任务通过。
本包包含预编译固件，服务器不需要另装交叉编译器。
原有real12_verify_01测试数据必须存在且哈希匹配；包内不重复携带音频或大型数据。
